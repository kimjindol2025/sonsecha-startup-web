LEGAL & COMPLIANCE

물환경보전법 제38조의2와 세차장 폐수 리스크

세차장은 단순 상가가 아닌 '폐수배출시설'입니다. 행정처분 및 과태료 위험을 사전에 방어해야 합니다.

🚨 법적 핵심 주의사항: '폐수배출시설 및 수질오염방지시설 운영기록부' 미보관 시 처벌

물환경보전법에 따라 세차장 사업자는 폐수처리시설의 일일 가동 상태, 약품 투입량, 슬러지 발생·위탁량을 매일 기록하고 3년간 사업장에 보관해야 합니다. 위탁 관리업체에 청소를 맡기더라도 최종 법적 책임은 대표자(점주)에게 있으며, 미작성·허위작성 적발 시 300만 원 이하의 과태료 및 조업정지 처분을 받게 됩니다.

본 통합 운영관리 시스템은 일일 계량기 수치 입력만으로 환경부 고시 서식에 맞춘 3년 보관용 일지를 자동 영구 보존합니다.

MVP IMPLEMENTATION SPEC · v1.2

1호점 수입·지출 장부와 일일 마감

1차 개발은 이 절을 따른다. 상단의 통합 화면은 후속 제품 구상이다.

목표

영업 중 수입과 지출을 거래 단위로 기록한다. 영업 종료 때 당일 거래와 결제수단별 증빙을 확인해 마감을 확정한다. 마감 합계에서 원래 거래와 품목을 다시 열 수 있어야 한다.

작업 범위

  1. 거래 입력·조회. 영업일 기본값은 한국 시간 오늘이다. 수입·지출·판매 환불을 구분하고 품목 또는 서비스명, 수량, 단가, 금액을 한 줄씩 기록한다. 수량 단위는 예를 들어 대·건·통·개로 표시한다. 한 거래에 여러 품목을 담을 수 있다. 지급·수납 수단, 담당자, 선택 메모와 증빙 참조를 남긴다. 환불은 원거래 참조와 사유를 남긴다.
  2. 마감 확인. 날짜별로 수입 합계, 판매 환불, 지출 합계, 수입·지출 차액과 결제수단별 합계를 표시한다. 합계에서 해당 거래 목록, 거래에서 품목 목록으로 이동한다. 카드 승인·취소는 단말 내역, 계좌이체는 계좌 입출금, 현금은 시작 시재와 마감 실사액으로 대조한다. 카드 입금 예정액과 실제 입금은 구분하고 동일 매출을 두 번 합산하지 않는다.
  3. 마감 확정·정정. 대조 전에는 확정할 수 없다. 차이가 있으면 차액과 사유를 기록하고 담당자가 확인한다. 마감 후 날짜를 다시 열면 당시 거래와 대조 결과를 읽기 모드로 표시한다. 정정할 때는 사유를 입력하고, 수정한 거래와 대조를 다시 확인해 새 개정본으로 저장한다.
  4. 개발 대상. daily-closing-app.html, src/daily-closing.js, src/daily-closing-domain.js를 추가한다. 기존 Vite 다중 페이지 입력과 운영 앱 메뉴에 연결하고 기존 CSS를 재사용한다. 기존 앱과 저장 키는 보존한다. 기존 날짜별 집계는 참고 자료로만 표시하며 거래로 자동 변환하지 않는다.
  5. 1차는 1호점의 같은 브라우저 프로필에 저장하는 수기 장부다. ERP, 재고 연동, 장비·폐수 마감, 실결제, 자동 카드·은행 연동, 서버 동기화와 증빙 파일 업로드는 후속 범위다.

저장과 계산

  • 별도 키 sonsecha-app-daily-ledger-v1에 schemaVersion과 날짜별 장부를 둔다. 날짜별 장부는 version, 편집 가능한 transactions, 확정본 배열 closings을 갖는다. 확정본마다 거래 전체의 사본, 대조값과 차이 사유, 합계, 담당자, UTC 확정 시각, 개정번호와 정정 사유를 저장한다.
  • 거래마다 고유 ID, 영업일, 기록 시각, 구분, 품목 배열, 결제 배열을 저장한다. 품목명과 단위는 필수다. 첫 버전의 수량은 양의 정수, 단가는 0 이상 원 단위 정수다. 줄 금액은 수량 × 단가, 거래 금액은 줄 금액의 합이다. 결제 배열 금액의 합은 거래 금액과 같아야 한다. 금액과 합계는 안전 정수 범위에서 검사하며 빈칸은 0과 구별한다.
  • 순수입 = 수입 − 판매 환불. 차액 = 순수입 − 지출. 지난 영업일의 판매 환불도 오늘 처리했으면 오늘 환불에 반영한다. 차액은 일일 거래 차액으로 표시한다. 카드 승인액이 포함될 수 있으므로 통장 잔액과 구분한다. RF 충전·사용, 자체 계좌 간 이체는 일반 판매 수입으로 중복 집계하지 않으며 1차 자동 계산에서 제외한다. 환불은 원 수입 거래와 사유가 필수다. 확정 거래와 정정 후보의 유효 환불을 대조해 원거래 총액을 초과하는 저장을 차단한다. 거래 없는 날은 ‘거래 없음 확인’과 현금 실사 후 확정한다.
  • 현금 예상 마감액 = 시작 시재 + 현금 수입 − 현금 환불 − 현금 지출. 대조 차이 = 확인 금액 − 장부 예상액. 카드·계좌는 해당 영업일의 수납과 지급을 각각 대조하며 카드 결제와 정산 입금을 같은 거래로 더하지 않는다. 대조값이 없으면 해당 수단의 대조는 미완료다.
  • 확정된 날짜의 장부는 직접 덮어쓰지 않는다. 정정 초안과 새 확정본은 저장 시 한 번에 반영한다. 동일 저장 키의 Web Lock 안에서 최신 날짜별 버전을 비교해 오래된 화면의 저장을 막는다. 저장 실패, 손상 JSON, 미지원 버전 또는 잠금 미지원 시 기존 데이터를 보존하고 편집 내용을 유지한다. 확정본과 이력을 JSON으로 내보낼 수 있게 한다.

검증과 완료 조건

  1. 기본세차 10,000원과 하부세차 3,000원을 한 거래로 입력하면 거래 1건, 품목 2줄, 카드 수입 13,000원이다. 세제 2통 × 5,000원을 현금 지출하면 지출 10,000원, 차액 3,000원이다. 시작 시재 20,000원이면 예상 현금은 10,000원이다. 현금 실사 9,000원이면 차이 −1,000원과 확인 사유가 필요하다.
  2. 거래 10건을 등록하고 합계에서 원거래 10건을 확인한다. 분할 결제, 이전 거래 환불, 증빙 누락, 미대조, 빈칸·음수·금액 불일치, 카드 정산 중복, 한국 시간 자정 경계를 검증한다.
  3. 390px 모바일 브라우저에서 메뉴 → 수입·지출 입력 → 대조 → 확정 → 새로고침 → 상세 재조회 → 정정을 검증한다. 이전 확정본과 원래 거래, JSON 백업을 확인한다. 두 탭 충돌, 저장 실패, 기존 앱 원본 보존과 GitHub Pages 하위 경로에서의 링크도 확인한다.
  4. 입력·기대값·실제값, 브라우저 캡처와 독립 검증 결과를 제출한다. 필수 검증이 모두 통과해야 PASS로 판정한다.
