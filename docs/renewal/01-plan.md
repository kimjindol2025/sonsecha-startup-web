## 1. 개편 목적

기존 창업 로드맵과 후보지 확인 기능을 중심으로, 방문자가 자신의 준비 단계에 맞는 정보를 찾고 기록한 뒤 필요한 상담을 요청하는 사이트로 개편한다. 솔깃의 주제별 탐색·추천 콘텐츠·읽기 편한 상세 화면을 참고하되 빅워시의 브랜드와 세차장 실무 콘텐츠로 구성한다.

핵심 경험은 “읽기 → 내 후보지에 적용하기 → 확인한 자료로 상담하기”다. 장비 구매와 공사 상담은 준비 상황에 맞춰 연결한다.

## 2. 현황 분석과 근거

이번 조사에서는 공개 HTTP 응답, HTML, 사이트맵과 공개 자바스크립트를 확인했다. 손세차 사이트의 실제 렌더링 화면, 모바일 배치, 폼 전송, 저장·복원 동작은 추가 검증 대상이다. 법령과 인허가 안내의 정확성 검수는 별도 작업이다.

| 항목 | 확인한 현황 | 개편 판단 |
|---|---|---|
| 메인 | 계약 전에 입지 가능성을 확인하라는 메시지 | 핵심 메시지 유지 |
| 창업 로드맵 | 12단계·계약 확인·서류·현장 체크 구성 | 개별 상세 페이지로 연결 |
| 허가 확인 | 후보지 기본 정보·질문·결과 화면 구성 | “자동 허가 판정”과 구분되는 안내 유지 |
| 전체 설명서 | 준비부터 상담까지 긴 이용 안내 | 시작 안내는 짧게, 전체 설명서는 보조 메뉴 |
| 제품몰 | 상품 검색·정렬·장바구니·견적서 구성 | 제품 영역으로 독립시키고 관련 글에서 연결 |
| 블로그 | 사이트맵 전체 72개 주소 중 글 주소 65개 | 실제 게시·본문·중복 여부 전수 대조 필요 |
| 글 상세 | 표본 2개 최초 HTML에 본문·H1 없고 공통 title 사용 | 자바스크립트 실행 후 상태와 검색 수집 상태 확인 후 개선 |
| 진행판 | 준비 중·개발 미리보기 안내 | 검증 전 정식 사용자 동선에서 체험 강조 제외 |
| 의견 보내기 | 이름·연락처·이메일 필수 표시 | 일반 의견과 상담 요청 분리 |
| 검색 기본 설정 | canonical·description·robots·sitemap 존재 | 페이지별 내용과 일치하는지 검증 |

65개 글 주소는 게시 완료 글 수를 뜻하지 않는다. 읽을 수 있는 본문과 노출 상태를 확인한 뒤 실제 운영 수량을 확정한다.

## 3. 대상 사용자와 제공 가치

| 사용자 | 방문 목적 | 첫 행동 | 최종 연결 |
|---|---|---|---|
| 창업 관심자 | 비용과 준비 순서를 이해 | 창업 가이드 읽기 | 사업 구상·계획 작성 |
| 후보지 보유자 | 계약 전에 확인할 조건 파악 | 후보지 확인 시작 | 확인 자료를 선택해 검토 요청 |
| 공사 준비자 | 설계·폐수·장비·공사 범위 정리 | 단계별 실무 자료 확인 | 설계·장비·공사 상담 |
| 운영자 | 장비·소모품·운영 개선 | 제품·운영 글 탐색 | 제품 문의·견적 요청 |

사이트의 사업 목적은 자료를 읽은 방문자의 상황을 이해하고, 필요한 검토·장비·설계·공사·운영 지원으로 연결하는 것이다. 모든 방문자에게 전체 컨설팅을 요구하지 않는다.

## 4. 정보 구조

상단은 로고, 주요 메뉴, 검색, 강조 버튼 “후보지 확인”으로 구성한다.

| 주요 메뉴 | 포함 콘텐츠 | 기존 기능 연결 |
|---|---|---|
| 창업 가이드 | 준비 순서·창업 비용·사업계획·12단계 | 메인 로드맵과 사업계획서 |
| 입지·허가 | 후보지·건축물·용도지역·환경·하수·계약 | /permit |
| 시공·장비 | 공사 준비·폐수 설비·전기·급수·장비 선택 | 실무 글과 상담 |
| 운영 노하우 | 세차 작업·안전·직원·고객·매출 관리 | 블로그 분류 확장 |
| 제품몰 | 제품 검색·제품 상세·장바구니·견적 | 기존 제품 기능 |

보조 메뉴: 전체 설명서, 내 준비 기록, 문의, 개인정보 안내, 사업자 정보. “내 준비 기록”의 공개 수준은 저장·복원과 개인정보 검증 후 결정한다.

기존 /blog, /permit, /guide와 글 주소는 유지한다. 분류를 바꿔도 기존 링크로 접근할 수 있게 한다. 주소 변경이 불가피한 경우 기존 주소와 새 주소의 일대일 연결표를 작성한다.

## 5. 메인 화면 구성

| 순서 | 영역 | 내용과 행동 |
|---|---|---|
| 1 | 대표 안내 | “손세차장 창업, 계약 전에 가능한 자리부터 확인하세요.” / 후보지 확인 시작 / 창업 순서 보기 |
| 2 | 준비 단계 선택 | 알아보는 중·후보지 찾는 중·계약 검토 중·공사 준비 중·운영 중 |
| 3 | 처음 읽을 글 | 비용 구성·후보지 확인·계약 전 질문 등 편집자가 선정한 글 3개 |
| 4 | 주제별 가이드 | 입지·계약·인허가·공사·장비·운영 카드 |
| 5 | 창업 12단계 | 단계 요약과 상세 보기, 저장된 체크 기록 연결 |
| 6 | 최근 업데이트 | 날짜와 주제가 보이는 최신 글 4~6개 |
| 7 | 현장 사례 | 실제 자료와 공개 동의가 확보된 사례만 노출 |
| 8 | 준비 단계별 제품 | 제품 용도와 선택 조건, 제품 상세로 연결 |
| 9 | 상담 안내 | 검토 가능한 내용·준비할 자료·요청 절차 안내 |
| 10 | 하단 정보 | 운영 사업자·연락처·개인정보·전체 설명서 |

대표 영역은 모바일 첫 화면에서 제목과 행동 버튼이 보이는 높이로 설계한다. 초기 버전은 고정 대표 문구를 사용한다. 추천 글 순환 배너와 애니메이션은 읽기·로딩 검증 후 도입한다.

“많이 읽은 글”은 실제 집계가 검증된 경우에만 사용한다. 집계 전에는 “먼저 읽으면 좋은 글”로 표시한다. 후기·시공 사례·수치·인기 순위를 만들어 넣지 않는다.

## 6. 콘텐츠 목록과 상세

목록에는 주제 필터, 검색, 최신순, 카드별 제목·요약·분류·업데이트 날짜를 제공한다. 결과가 없거나 불러오기 실패한 경우 빈 화면 대신 원인과 다시 시도할 행동을 표시한다.

글 상세의 기본 순서는 다음과 같다.

1. 상위 분류와 현재 위치
2. 구체적인 제목, 작성일·수정일, 검토 기준일
3. 핵심 요약 3개
4. 이 글이 필요한 사람과 준비 자료
5. 목차와 단계별 설명
6. 체크리스트·도면·사진·표 등 실무 자료
7. 자주 묻는 질문과 공식 출처
8. “내 후보지에 확인사항 기록하기”
9. 관련 글과 필요한 경우 제품·상담 연결

읽는 시간은 본문 길이로 계산한 추정치로 표시한다. 인허가 글에는 지역과 현장 조건에 따른 확인 범위를 설명하고 근거 링크와 확인일을 둔다. 법령 변경이나 검토 기한 경과 시 운영자가 재검토할 수 있게 한다.

본문은 좁고 편한 읽기 폭, 충분한 줄 간격, 명확한 소제목을 사용한다. 데스크톱 목차와 모바일 접이식 목차를 제공한다. 글자 확대 시 버튼과 본문이 겹치지 않아야 한다.

## 7. 후보지 확인과 상담 동선

후보지 등록 → 확인 질문 기록 → 확인·미확인·추가 확인 구분 → 결과 요약 → 공유 자료 선택 → 제출 전 미리보기 → 상담 요청 → 접수번호 확인.

주소만 입력해서 허가 가능 여부를 확정하지 않는다. 사용자가 체크한 완료와 관할 기관의 확인 완료를 구분한다. 각 항목은 확인일·출처·근거 메모를 함께 관리한다.

상담 제출 전 주소·연락처·메모·사진 중 전달되는 내용을 보여준다. 다른 후보지 자료가 섞이지 않도록 후보지 단위로 묶는다. 중복 클릭으로 같은 요청이 여러 번 생성되지 않게 한다.

상담 접수는 서버 저장 성공 후에만 완료로 표시한다. 실패하면 입력을 유지하고 재시도 방법을 제공한다. 응답 시간과 제공 서비스는 실제 운영 가능한 범위를 확정한 뒤 표시한다.

## 8. 제품과 견적

제품에는 용도·주요 사양·설치 조건·가격 또는 가격 문의 상태를 구분한다. 정보성 글과 자사 판매 제품 연결을 명확히 표시한다.

장바구니·수량·견적 기능은 기존 동작을 보존한다. 가격 문의 상품은 0원 상품처럼 보이지 않게 한다. 배송·설치·부가세 조건을 합계 가까이에 표시하고 간이견적과 최종견적을 구분한다. 제품 문의를 주문 확정이나 결제 완료로 표현하지 않는다.

## 9. 디자인 방향

빅워시의 현장 전문성을 보여주는 딥블루·블루·화이트를 기본으로 하고, 읽는 영역에는 옅은 회색 배경을 사용한다. 솔깃의 넉넉한 여백과 콘텐츠 카드 체계를 참고한다.

| 요소 | 적용 원칙 |
|---|---|
| 대표 이미지 | 실제 세차장·시공·장비 사진 우선 |
| 보조 이미지 | 이해를 돕는 도식과 필요 시 AI 이미지 표시 |
| 카드 | 이미지 비율 통일, 제목 우선, 주제와 날짜 명확히 |
| 강조 버튼 | 한 화면의 주요 행동을 우선 구분 |
| 모바일 | 한 열 중심, 긴 표는 별도 스크롤, 모달 내부 스크롤 지원 |
| 접근성 | 키보드 이동·초점·명확한 레이블·색 외 상태 표시 |
| 움직임 | 장식보다 읽기 우선, 움직임 줄이기 설정 반영 |

신한 로고·원문·고유 이미지·애니메이션을 재사용하지 않는다. 빅워시 자산과 독자 콘텐츠로 제작한다.

## 10. 콘텐츠 운영

글마다 제목·고유 주소·요약·분류·태그·본문·대표 이미지·출처·기준일·검토 상태를 관리한다. 추천 글은 운영자가 선정하고 노출 근거를 구분한다.

기존 65개 글 주소를 기준으로 실제 데이터·공개 상태·본문·중복·깨진 링크를 대조한다. 삭제보다 수정·통합을 우선하며 통합 시 이전 주소의 연결을 유지한다.

초기 운영은 기존 관리 기능을 우선 재사용한다. 관리자 시스템 재개발, 회원제와 외부 CMS 도입은 이번 범위에 포함하지 않는다.

## 11. 검색과 성능

각 글의 최초 HTML에서 고유 title·description·canonical·H1·핵심 본문을 확인할 수 있게 한다. 현재 코드와 운영 방식을 조사한 뒤 사전 생성 또는 서버 렌더링 방식을 결정한다. 본문 없는 공통 HTML 문제와 실제 검색 노출 문제를 구분해 검증한다.

게시된 정상 페이지만 사이트맵에 포함하고, 없는 글은 실제 404 상태를 반환한다. 비공개·관리·개인 기록 페이지의 검색 정책을 분리한다. robots.txt는 접근 권한을 대신하지 않는다.

이미지 크기를 화면에 맞게 제공하고 대표 이미지 이외에는 지연 로딩한다. 불필요한 대형 영상과 장식 라이브러리를 초기 범위에서 제외한다. 성능 목표는 모바일 측정 조건을 고정해 LCP 2.5초 이하·CLS 0.1 이하를 제안하며, 달성 여부는 구현 후 측정한다.

## 12. 개발 범위와 진행 순서

| 단계 | 작업 | 산출물 |
|---|---|---|
| 현황 검증 | 화면·모바일·데이터·현재 코드·기존 동작 조사 | 화면 목록·글 대조표·기능 기준선 |
| 기획 | 이번 개편의 화면·동선·우선순위 확정 | 본 기획서 확정본 |
| 구현명세 | 경로·컴포넌트·데이터·오류·저장·이관 정의 | 구현명세서 |
| 작업 지시 | 변경 파일·금지 범위·검증 항목 지정 | 단일 목표별 작업 지시 |
| 구현 | 격리 환경에서 메인·목록·상세 순서로 작업 | 검토 가능한 미리보기 |
| 독립 검증 | 기존 기능 회귀와 신규 동선 검증 | 증거·결과·잔여 문제 |
| 운영 적용 | 검토된 변경만 반영하고 실제 공개 화면 확인 | 배포 기록·복귀 방법 |

191 서버 작업은 기획서 → 구현명세서 → 작업 지시 → 구현 → 독립 검증 순서를 따른다. 기존 미커밋 변경과 사용자 자료를 보존한다. 이번 요청의 산출물은 기획서이며 운영 사이트 적용은 별도 단계다.

1차는 메인·기존 글 분류·목록·상세·검색 기본 정보와 기존 기능 보존에 집중한다. 이후 후보지 연계와 상담 편의 개선을 진행한다. 로그인 기반 동기화·진행판 정식 공개·개인화 추천은 별도 범위로 둔다.

## 14. 최종 제안

기존의 깊이 있는 창업 실무와 기록 기능을 중심에 두고, 메인은 쉽게 고르는 입구로 바꾼다. 블로그는 읽고 끝나는 글에서 후보지 확인과 다음 준비로 이어지는 안내서로 발전시킨다. 구현 전 첫 과제는 실제 화면과 기존 저장 기능의 기준선을 확보하고, 이를 바탕으로 구현명세서를 만드는 것이다.
