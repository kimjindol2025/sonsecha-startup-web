# 단계별 세부 앱 구현 문서

## 목적

현재 로드맵은 `20단계 안내 + 후보지별 체크 + 메모` 중심이다. 다음 구현의 목적은 이를
`실제로 입력하고, 판정하고, 증빙을 모으고, 다음 행동까지 관리하는 단계별 앱`으로
확장하는 것이다.

이 문서는 다음 두 가지를 먼저 고정한다.

1. 단계별 세부 앱의 공통 데이터 구조
2. 1~20단계 각각에 어떤 입력과 판정이 들어가야 하는지

## 구현 원칙

- 단계별 화면은 설명 페이지가 아니라 입력형 업무 화면이어야 한다.
- 후보지별로 모든 단계 데이터가 분리 저장되어야 한다.
- 사용자가 입력하지 않은 사실을 자동 생성하지 않는다.
- 각 단계는 `체크`, `판정`, `메모`, `담당기관`, `일정`, `금액`, `증빙`을 담을 수 있어야 한다.
- 사업계획서, 상담 요청, 관리자 검토 화면은 같은 단계 데이터를 재사용해야 한다.

## 공통 데이터 모델

후보지 한 건마다 아래 구조를 갖는다.

```json
{
  "id": "candidate-1",
  "name": "옥정동 부지",
  "address": "경기도 ...",
  "status": "conditional",
  "stageRecords": {
    "1": {
      "checked": true,
      "decision": "possible",
      "summary": "건축물대장과 토지이용계획 확보",
      "notes": "오수관 위치는 추가 확인 필요",
      "owner": "대표",
      "agency": "양주시 건축과",
      "dueDate": "2026-08-20",
      "amount": "",
      "evidence": [
        { "kind": "link", "label": "건축물대장", "value": "..." },
        { "kind": "file", "label": "토지이용계획확인서", "value": "..." }
      ],
      "checks": [
        { "id": "1-1", "label": "건축물대장 확인", "done": true },
        { "id": "1-2", "label": "토지이용계획 확인", "done": true }
      ],
      "nextAction": "하수도 담당자와 연결 가능 여부 문의"
    }
  }
}
```

## 단계 카드 공통 UI

각 단계는 같은 구조를 쓴다.

1. 상단 요약
2. 공식 리서치 요약
3. 세부 체크리스트
4. 입력 폼
5. 판정과 다음 행동
6. 증빙 목록

### 상단 요약

- 단계 번호
- 단계명
- 현재 판정: `미확인 / 가능 / 조건부 가능 / 불가`
- 담당자
- 마감일
- 마지막 수정일

### 입력 폼 공통 필드

- `summary`: 한 줄 요약
- `notes`: 자유 메모
- `owner`: 담당자
- `agency`: 문의 기관 또는 업체
- `dueDate`: 다음 확인일
- `amount`: 관련 금액
- `decision`: 판정
- `nextAction`: 다음 행동

### 증빙 공통 필드

- 링크
- 파일명 또는 첨부 경로
- 사진
- 공문/답변 메모
- 견적서

## 후보지 대시보드

후보지 화면에는 다음 요약이 필요하다.

- 전체 20단계 진행률
- `불가` 단계 수
- `조건부 가능` 단계 수
- 미확인 단계 수
- 합계 예정금액
- 가장 가까운 다음 일정 3개

## 단계별 구현 문서

아래 내용은 각 단계에 실제로 넣을 입력형 화면 기준이다.

### 01. 후보지 주소 확인

목적:
- 주소 기준으로 후보지 검토의 시작점을 고정한다.

주요 입력:
- 도로명주소
- 지번
- 동/층/호
- 실사용 면적
- 주변 민원 메모

체크:
- 건축물대장 확보
- 토지이용계획 확보
- 등기사항증명서 확인
- 오수관/우수관 위치 확인
- 진입로 사진 확보

증빙:
- 건축물대장
- 토지이용계획확인서
- 현장 사진

### 02. 건축사 사전검토

목적:
- 세차장 용도 가능 여부와 구조물 이슈를 1차 판정한다.

주요 입력:
- 건축사명
- 검토일
- 용도변경 필요 여부
- 캐노피/기계실/경량철골 검토 메모

체크:
- 세차장 용도 가능 여부
- 주차 기준 충족 여부
- 피난/소방 기준
- 구조 보강 필요 여부

증빙:
- 건축사 검토 메모
- 개략 평면도

### 03. 조건부 임대차계약

목적:
- 인허가 불가 시 빠져나올 수 있는 계약 구조를 만든다.

주요 입력:
- 임대인
- 계약일
- 계약금
- 특약 반영 여부

체크:
- 용도변경 동의
- 굴착/배관 공사 동의
- 불허 시 계약금 반환 특약
- 원상복구 범위 명시

증빙:
- 임대차계약서
- 특약 캡처 또는 스캔

### 04. 세차폐수 처리계획 수립

목적:
- 폐수, 집수, 재이용수 구조를 설계한다.

주요 입력:
- 1일 예상 세차 대수
- 차종별 물 사용량
- 침전조/집수조 개념
- 최종 배출 경로

체크:
- 우수/폐수 분리
- 집수조 위치
- 유수분리 계획
- 슬러지 처리 계획

증빙:
- 배수계통 스케치
- 처리계통도

### 05. 폐수배출시설 해당 여부 및 설치 허가·신고

목적:
- 환경 절차가 허가인지 신고인지 제외인지 정리한다.

주요 입력:
- 환경부서 담당자
- 협의일
- 대상 여부
- 제출 서류 목록

체크:
- 폐수배출시설 해당 여부
- 특정수질유해물질 여부
- 허가/신고/제외 구분
- 가동 전 추가 절차 확인

증빙:
- 민원 답변
- 제출 서류 목록

### 06. 건축물 용도변경

목적:
- 기존 용도를 세차장 운영 구조에 맞게 변경한다.

주요 입력:
- 현재 용도
- 목표 용도
- 허가/신고 유형
- 보완시설 목록

체크:
- 주차
- 장애인 편의
- 소방
- 피난
- 구조 보강

증빙:
- 용도변경 신청서
- 허가/신고 결과

### 07. 배수설비·차량 출입 관련 절차

목적:
- 배수 연결과 차량 진출입 합법성을 확보한다.

주요 입력:
- 하수 연결 위치
- 관경/깊이
- 도로점용 필요 여부
- 출입구 허가 메모

체크:
- 배수설비 설치신고
- 오수/우수 구분
- 차량 출입 허가
- 원인자부담금 여부

증빙:
- 배수설비 도면
- 허가 또는 협의 답변

### 08. 승인 도면에 따른 시설공사

목적:
- 승인도면 기준으로 시공하고 변경을 통제한다.

주요 입력:
- 시공사
- 공사기간
- 공정별 금액
- 변경요청 발생 여부

체크:
- 트렌치/방수
- 전기 증설
- 급배수
- 기계실
- 경보기/비상차단

증빙:
- 공정 사진
- 준공도면 초안

### 09. 준공 확인과 건축물대장 반영

목적:
- 승인과 실제 시공이 일치하는지 최종 확인한다.

주요 입력:
- 준공일
- 대장 반영일
- 미비사항

체크:
- 사용승인
- 소방 확인
- 대장 반영
- 배수설비 준공검사

증빙:
- 사용승인서
- 새 건축물대장

### 10. 폐수시설 가동시작 신고와 시운전

목적:
- 가동 전 실제 운전과 비상상황을 점검한다.

주요 입력:
- 시운전일
- 가동신고일
- 시운전 결과

체크:
- 넘침 없음
- 펌프 정상
- 고수위 경보 정상
- 배출구 일치

증빙:
- 시운전 체크표
- 가동신고 접수자료

### 11. 사업자등록과 영업 준비

목적:
- 세무·결제·업태를 실제 영업 구조에 맞춘다.

주요 입력:
- 사업자등록일
- 업태/종목
- 결제수단
- 현금영수증/카드단말기 상태

체크:
- 사업자등록 완료
- 업태/종목 확정
- 사업용 계좌 준비
- 예약/선불권 구조 검토

증빙:
- 사업자등록증
- 카드단말기 계약

### 12. 보험·안전·운영기준 확인 후 개업

목적:
- 개업 전 보험, 안전, 차량 분쟁 기준을 확정한다.

주요 입력:
- 보험사
- 보장범위
- MSDS 비치 여부
- 차량 사진촬영 절차

체크:
- 영업배상책임보험
- 차량 손상 보장범위 확인
- MSDS 비치
- 안전교육 완료

증빙:
- 보험증권
- 교육기록

### 13. 오픈 첫 30일 운영 안정화

목적:
- 개업 직후 운영 기준선을 숫자로 잡는다.

주요 입력:
- 일매출
- 입차 대수
- 장비오류 횟수
- 손세차 보완 요청

체크:
- 4주 로그 누적
- 오류 복구시간 기록
- 이벤트 종료 후 정상매출 확인

증빙:
- 일일 운영일지

### 14. 손세차·셀프 보완 동선 정리

목적:
- 노터치와 손세차 보완 흐름의 병목을 없앤다.

주요 입력:
- 드라잉존 체류시간
- 손세차 마감 위치
- 셀프 구역 혼잡 시간대

체크:
- 대기줄 분리
- 보행/차량 동선 분리
- 야간 동선 테스트

증빙:
- 동선 스케치
- 혼잡 시간대 사진

### 15. 가격·회원권·구독 정책 조정

목적:
- 가격과 선불상품 구조를 실제 운영에 맞춘다.

주요 입력:
- 기본 코스 가격
- 손세차 추가 옵션 가격
- 회원권/구독권 정책
- 환불 기준

체크:
- 가격표 확정
- 유효기간 표시
- 환불정책 명시
- 지급수단 구조 검토

증빙:
- 가격표
- 회원권 약관

### 16. 민원·재세차·환불 기준 운영

목적:
- 분쟁 대응을 표준화한다.

주요 입력:
- 민원 유형
- 재세차 기준
- 환불 기준
- CCTV 보관기간

체크:
- 민원 프로세스 문서화
- CCTV 운영방침
- 입고 전 사진 절차
- 책임자 승인 절차

증빙:
- 민원 응대표
- CCTV 안내문

### 17. 약품·소모품·재고 관리

목적:
- 약품 원가와 소모품 부족을 통제한다.

주요 입력:
- 품목명
- 공급사
- 최소재고
- 월 사용량
- 희석비율

체크:
- 재고표 작성
- MSDS 확보
- 혼합금지표 비치
- 손세차용/자동세차용 분리

증빙:
- 재고표
- MSDS

### 18. 정기점검·동절기 대비

목적:
- 예방정비와 동파 대응을 운영체계로 만든다.

주요 입력:
- 월간 점검일
- 장비사 방문일
- 겨울철 체크리스트
- 장애 연락망

체크:
- 예방정비 달력
- 열선/보온 점검
- 결빙 대응 절차
- 자체 대응/장비사 대응 범위 구분

증빙:
- 점검기록
- 동절기 점검표

### 19. 일매출·원가·피크타임 분석

목적:
- 회전율과 원가 구조를 기반으로 손익을 다시 본다.

주요 입력:
- 시간대별 입차
- 코스별 매출
- 손세차 보완 매출
- 전기/수도/약품 원가

체크:
- 피크타임 구분
- 코스별 이익 기여도 계산
- 비수기 손익분기 재산정

증빙:
- 월간 분석표

### 20. 추가 베이·확장 여부 판단

목적:
- 감이 아니라 운영 데이터로 추가 투자 여부를 판단한다.

주요 입력:
- 3~6개월 누적 매출
- 대기줄 빈도
- 손세차 인력 부족 여부
- 확장 예상비

체크:
- 병목 원인 분석
- 베이 확장 vs 동선 개선 비교
- 회수기간 계산
- 위험요인 정리

증빙:
- 확장 검토 메모
- 투자안 비교표

## 구현 순서

1. 공통 `stageRecords` 데이터 모델 추가
2. 후보지별 단계 상세 패널 UI 추가
3. 1~5단계 입력형 폼 구현
4. 저장/불러오기/판정 표시 연결
5. 상담 요청과 사업계획서에 `stageRecords` 연결
6. 같은 패턴으로 6~20단계 확장

## 1차 구현 범위

먼저 1~5단계를 실제 사용 가능한 수준으로 만든다.

이 범위에 포함할 기능:

- 단계별 입력 폼
- 단계별 판정
- 담당기관·일정 관리
- 금액/메모 저장
- 증빙 링크 3개까지 저장
- 후보지 대시보드 요약 반영

이 범위에 포함하지 않는 기능:

- 서버 파일 업로드
- OCR
- 외부 캘린더 연동

## 저장 정책

- 기존 후보지 저장 키 `sonsecha-candidates-v2`를 유지한다.
- 새 단계 데이터는 각 후보지 객체 내부 `stageRecords`에 추가한다.
- 기존 `stepChecks`, `stepStatuses`, `detailChecks`, `detailNotes`는 호환용으로 유지한다.
- 새 UI는 가능하면 `stageRecords`를 기준으로 표시하고, 기존 값은 마이그레이션한다.
