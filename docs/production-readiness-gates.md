# 손세차장 창업 로드맵 운영 준비도 게이트

- 문서 상태: 운영 검수 기준 초안
- 작성일: 2026-11-10
- 대상: `sonsecha-startup-web`
- 목표: 기능이 응답한다는 이유만으로 상용 운영 완료로 판정하지 않고, 보안·데이터·복구·배포·회귀 검증을 순서대로 통과시킨다.

## 판정 원칙

1. 게이트는 아래 순서대로 진행한다.
2. 이전 게이트가 `PASS`가 아니면 다음 게이트를 시작하지 않는다.
3. `FAIL`은 재현 절차와 증거를 남긴 뒤 수정하고 같은 게이트를 다시 검증한다.
4. 같은 게이트가 3회 이상 연속 실패하면 우회·강제 배포하지 않고 `BLOCKED`로 보고한다.
5. `BLOCKED` 보고에는 실패 횟수, 마지막 오류, 영향 범위, 보존된 로그·백업 위치, 다음 의사결정이 필요한 내용을 포함한다.
6. 운영 데이터·비밀값·관리자 인증정보는 테스트에 사용하거나 로그에 출력하지 않는다.

## 상태 값

| 상태 | 의미 |
|---|---|
| `NOT_STARTED` | 아직 검증하지 않음 |
| `IN_PROGRESS` | 현재 검증 중 |
| `PASS` | 해당 기준을 모두 만족함 |
| `FAIL` | 수정 후 재검증 필요 |
| `BLOCKED` | 같은 게이트 3회 이상 실패하여 사용자 보고 필요 |
| `WAIVED` | 운영자가 위험과 근거를 확인하고 명시적으로 예외 승인함 |

## 게이트 순서

### Gate 0 · 변경 범위와 비밀값

통과 기준:

- 현재 작업의 변경 파일을 목록화한다.
- `git diff --check`가 통과한다.
- `.env*`, SMTP 앱 비밀번호, 관리자 인증정보, 로그, `node_modules`, 운영 `data/`가 커밋 대상에 없다.
- 기존 상품·후보지·상담·이메일 기능과 무관한 변경은 포함하지 않는다.

현재 상태: `PASS` — 이번 운영 준비도 문서 추가 전 기준.

### Gate 1 · 관리자 인증과 권한

통과 기준:

- 비인증 `/admin` 요청은 `/admin/login`으로 이동한다.
- 비인증 관리자 API는 `401`을 반환한다.
- 로그인 성공·실패·로그아웃·세션 만료를 확인한다.
- 초기 관리자 비밀번호가 로그·응답·오류에 출력되지 않는다.
- AI 상품등록 API는 별도 비밀키 없이는 실행되지 않는다.

현재 상태: `PASS` — 초기 비밀번호는 `ADMIN_INITIAL_PASSWORD` 또는 보호된 파일에서만 읽고, 로그에는 인증정보를 출력하지 않는다. 기존 인증 파일이 있는 운영 환경의 로그인·비인증 API도 확인했다.

### Gate 2 · 입력 검증과 개인정보

통과 기준:

- 이름·전화번호·이메일·상담 내용의 길이와 형식을 검증한다.
- HTML·스크립트 입력이 화면·이메일·관리자 화면에서 실행되지 않는다.
- 후보지 주소와 메모의 공유 범위를 사용자가 선택할 수 있다.
- 상담 사진의 MIME·파일 시그니처·용량·개수를 검증한다.
- SMTP 앱 비밀번호와 고객 개인정보가 로그에 남지 않는다.

현재 상태: `PASS` — 입력 형식·길이·동의·사진 검증과 escape를 확인했고, 상태 변경 API에 same-origin 검증을 추가했다.

### Gate 3 · 데이터 무결성과 원자성

통과 기준:

- 상품·콘텐츠 저장 중간 실패 시 기존 데이터가 보존된다.
- 동시에 발생한 관리자 저장 요청이 서로의 변경을 덮어쓰지 않는다.
- 상담 생성·메시지·첨부파일 DB 기록과 실제 파일의 상태가 일치한다.
- 첨부파일 저장 실패 시 DB 레코드가 롤백되거나 재처리 가능한 상태로 남는다.
- SQLite 무결성 검사와 저장 파일 권한을 확인한다.

현재 상태: `PASS` — 첨부파일 DB 기록·파일 저장·경로 갱신을 SQLite `BEGIN IMMEDIATE` 트랜잭션으로 묶고 실패 시 롤백·파일 정리를 적용했다. 상품·콘텐츠·AI 상품 저장은 프로세스 내 직렬화 큐로 read-modify-write 손실을 방지했으며, 격리 서버에서 첨부파일 실패 롤백과 동시 상품 수정 보존을 확인했다.

### Gate 4 · 백업과 복구

통과 기준:

- 운영 데이터 백업을 실행하고 권한 `600`을 확인한다.
- 상품·상담·피드백·콘텐츠가 백업에 포함된다.
- SMTP 환경변수와 관리자 인증정보는 백업 아카이브에 포함되지 않는다.
- 별도 임시 디렉터리에서 복원 테스트를 완료한다.
- 백업 보관 기간과 삭제 정책이 자동화되어 있다.

현재 상태: `PASS` — 백업 실행·민감파일 제외·권한 600·별도 임시 디렉터리 복원 리허설을 완료했고, 현재 호스트 `crontab`에 프로젝트 백업 스케줄을 중복 없이 등록했다. `crond`도 active 상태다.

### Gate 5 · 운영 안정성과 장애 복구

통과 기준:

- `/healthz`가 정상 상태와 서비스 식별자를 반환한다.
- 서버 재시작 후 40330이 다시 수신된다.
- SMTP 미설정·SMTP 실패·DB 오류가 서버 전체 종료로 이어지지 않는다.
- 요청 제한·로그인 제한·이메일 제한이 장애 상황에서도 예측 가능하다.
- SIGTERM, 로그 회전, 재시작 backoff를 확인한다.

현재 상태: `PASS` — health·40330·SMTP 실패 격리·로그인 제한·SIGTERM graceful shutdown·재시작 backoff를 격리 런처에서 확인했다. ecosystem에 표준 PM2 backoff 설정을 추가하고, 실제 `kim-pm2` 런처에도 1~15초 제한 지수 backoff를 적용했다. 로그는 logrotate 설정·crontab·강제 회전·권한 600을 확인했다.

### Gate 6 · 자동 회귀와 브라우저

통과 기준:

- `npm run build`가 통과한다.
- 후보지 체크·메모·판정·localStorage 복원 테스트가 통과한다.
- 사업계획서·제품몰·관리자 인증·상담 요청 테스트가 통과한다.
- 공개 상품 API와 관리자 상품 API 권한 테스트가 통과한다.
- 데스크톱·모바일 브라우저에서 가로 넘침·콘솔 오류가 없다.

현재 상태: `PASS` — 격리 Chrome에서 사업계획서·제품몰·상담 화면의 데스크톱/모바일 smoke를 통과했고, 상담·관리자 인증·공개 상품 이미지 API 회귀 테스트를 통과했다. SMTP 미설정 503 저장 계약도 테스트에 반영했다.

### Gate 7 · 배포와 롤백

통과 기준:

- 변경 커밋·원격 브랜치·배포 대상 서버를 식별한다.
- 운영 데이터와 환경파일을 보존한 상태로 코드만 배포한다.
- 배포 전 백업과 배포 후 health/API/관리자 인증 확인을 완료한다.
- 이전 릴리스로 코드만 되돌리는 절차를 실제로 확인한다.
- 공식 도메인 응답이 배포 커밋과 일치한다.

현재 상태: `FAIL` — 최신 readiness 개선분은 아직 커밋·공식 도메인 배포 전이다.

## 현재 우선순위

| 순서 | 작업 | 게이트 | 상태 |
|---:|---|---|---|
| 1 | 초기 관리자 비밀번호 로그 제거 | Gate 1 | `PASS` |
| 2 | 첨부파일 DB/파일 저장 원자성 보강 | Gate 3 | `PASS` |
| 3 | 상품·콘텐츠 저장 동시성 제어 | Gate 3 | `PASS` |
| 4 | 백업 스케줄·복원 리허설 | Gate 4 | `PASS` |
| 5 | 운영 health·장애 복구 확인 | Gate 5 | `PASS` |
| 6 | CI 회귀 테스트 확장 | Gate 6 | `PASS` |
| 7 | 커밋·공식 배포·롤백 검증 | Gate 7 | `FAIL` |

## 완료 정의

다음 단계 작업은 Gate 1부터 Gate 7까지 모두 `PASS`가 되거나, 각 예외가 운영자의 명시적인 `WAIVED` 승인을 받은 경우에만 진행한다. 하나라도 `FAIL`이면 수정 후 같은 게이트를 반복한다. 동일 게이트의 연속 실패가 3회가 되면 작업을 중지하고 이 문서의 실패 기록과 함께 보고한다.
