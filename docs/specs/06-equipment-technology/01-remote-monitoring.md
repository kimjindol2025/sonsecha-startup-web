# [기획서] 세차장 장비 원격관제

> **카테고리**: 06 장비·기술 서비스 (C급 · 확장)  
> **앱 ID**: `app-equipment-remote-monitoring`  
> **문서 상태**: 제품 범위 조사 초안 — 구현은 [구현 명세 v1.0](./01-remote-monitoring-implementation.md)의 데모 MVP만 대상으로 한다. 실제 장비 연동은 미확정.  
> **목적**: 여러 세차장의 장비 상태와 장애를 원격에서 확인하고, 현장 출동이 필요한 문제를 빠르게 분류한다.

## 1. 문제와 대상 사용자

> Codex 구현 요청은 요약 기획만 보고 진행하지 말고, [구현 명세 v1.0](./01-remote-monitoring-implementation.md)의 화면, 데이터 계약, 범위 제한, 인수 기준을 따른다.

점주와 본사 운영자는 매장에 직접 가지 않으면 장비가 정상 가동 중인지 알기 어렵다. 장애가 발생해도 오류 발생 시점, 장비 상태, 현장 조치 여부가 한곳에 남지 않아 전화 확인과 출동 판단이 반복된다. 장비 제조사마다 통신 인터페이스가 다를 수 있으므로 범용 원격 제어를 전제로 하지 않고, 실제 지원 인터페이스를 확인한 뒤 연결 범위를 정한다.

| 사용자 | 주요 작업 |
| --- | --- |
| 점주·매장 관리자 | 보유 장비의 현재 상태·장애 알림 확인, 점검 또는 AS 요청 |
| 본사 운영자 | 여러 지점의 장애·가동 상태 비교, 반복 장애 추적 |
| 현장 직원 | 알림 확인, 현장 점검 결과와 사진 기록 |
| 제조사·AS 기사 | 승인된 정비 티켓에 한해 필요한 진단 정보 확인 |

## 2. 핵심 가치와 성공 지표

- 전화로 현장 상태를 다시 묻는 횟수를 줄이고, 장애 발생부터 인지까지 걸린 시간을 측정한다.
- 지점·장비별 통신 단절과 장애 이력을 한 화면에서 확인한다.
- AS 요청에 오류코드·발생시간·현장 조치 내역을 함께 전달한다.
- 파일럿에서는 알림 전달 성공률, 장애 인지 시간, 불필요한 출동 건수, 장비 연결 유지율을 측정한다. 목표 수치는 기준선 조사 후 정한다.

## 3. MVP 범위

1. 지점, 장비, 장비 모델, 설치 위치, 연동 방식 등록
2. 장비별 마지막 통신 시각과 연결 상태 표시
3. 제조사 또는 게이트웨이가 제공하는 가동 상태·오류 코드·선택 센서값 수집
4. 통신 단절·오류 발생 알림과 확인/담당자 지정
5. 장애 이벤트 타임라인, 현장 점검 메모·사진, AS 티켓 연결
6. 기간별 가동률·장애 건수·장애 지속시간 보고서

MVP의 제어 기능은 **읽기 전용**으로 제한한다. 장비 전원, 펌프, 리셋, 운전 파라미터를 원격에서 변경하는 기능은 제조사 승인, 안전 인터록, 현장 수동 복구 절차와 파일럿 검증을 거친 별도 단계로 둔다.

## 4. 주요 흐름

1. 관리자가 지점과 장비를 등록하고 제조사·모델·지원 인터페이스를 확인한다.
2. 설치 담당자가 승인된 게이트웨이 또는 제조사 연동을 설정하고 시험 데이터를 확인한다.
3. 서비스는 상태 변경과 오류 이벤트를 기록하며 장비별 마지막 통신 시각을 갱신한다.
4. 임계 조건 또는 오류 코드 발생 시 담당자에게 알리고, 확인·현장 점검·AS 요청 상태를 기록한다.
5. 점주와 본사는 기간별 장애 및 가동 현황을 확인한다.

## 5. 데이터 및 연동 설계

핵심 데이터는 `site`, `equipment`, `equipment_model`, `telemetry`, `event`, `alert`, `maintenance_ticket`, `user_role`로 구성한다. 각 이벤트에는 장비 ID, 발생·수신 시각, 원천 시스템, 오류코드, 측정값 단위, 연동 상태를 저장한다. 위치·장비별 접근권한을 적용하고, 원본 이벤트의 보존기간은 고객 요구와 운영비 검토 후 정한다.

연동은 제조사 API/프로토콜 확인을 먼저 수행하고, 필요하면 현장 게이트웨이에서 클라우드로 텔레메트리만 전달한다. OPC UA는 권한 기반 읽기/쓰기와 인증서·감사 기능을 제공하는 후보 표준이며, MQTT는 메시지 전달 QoS와 TLS 사용을 정의한다. 실제 세차 장비가 해당 표준을 지원한다는 뜻은 아니므로 모델별 검증이 선행되어야 한다.

## 6. 보안과 안전 요구사항

- PLC·RTU를 인터넷에 직접 노출하지 않고, 제어망과 외부 서비스 사이에 분리·방화벽·DMZ를 둔다.
- 장비와 계정별 최소 권한을 적용하며 기본 운영 권한은 읽기 전용으로 둔다.
- 원격 제어가 후속 단계에서 승인되면 다중 승인 또는 현장 확인, 작업 로그, 시간 제한 권한, 비상 중단과 로컬 수동 운전 기준을 정의한다.
- 전송 중 데이터 보호, 장치 식별, 보안 업데이트, 인터페이스 접근제어, 통신 장애 감지·재연결 상태를 설계한다.
- 운영자·기사 접근, 권한 변경, 설정 변경은 감사 기록으로 남긴다.

## 7. 수익모델 가설과 단계

**가설**: 초기 설치·연동 비용과 지점 또는 장비 단위 월 구독을 기본으로 하고, 제조사 AS 연계·예방정비 리포트를 부가 서비스로 제공한다. 공개 자료만으로 국내 가격과 절감 효과는 확인하지 못했으므로 파일럿 인터뷰와 유료 의향 확인 전에는 가격을 확정하지 않는다.

| 단계 | 범위 | 통과 조건 |
| --- | --- | --- |
| 0. 연동성 확인 | 주요 제조사·모델 인터뷰, 통신 방식과 데이터 항목 확인 | 데이터 읽기 권한과 설치·운영 책임 합의 |
| 1. 읽기 전용 파일럿 | 3~5개 점포 가설로 상태·알림·이력 검증 | 통신 안정성, 알림 유용성, 현장 업무 적합성 확인 |
| 2. 운영 확장 | 다지점 대시보드, 정비 티켓, 보고서와 구독 실험 | 반복 사용 및 지불 의향 확인 |
| 3. 선택적 제어 | 제조사 승인 모델에 한해 제한된 명령 지원 | 위험분석, 인터록, 복구 시험 및 책임 주체 확정 |

## 8. 검증 질문과 주요 위험

- 제조사·모델별 원격 모니터링 포트/API가 허용되는가? 데이터 소유자와 연동 책임자는 누구인가?
- 점주가 실제로 확인하고 싶은 상태값과 현재 확인 주기는 무엇인가?
- 월간 장애시간, 출동 빈도·비용의 현 기준선을 제공할 수 있는가?
- 매장 인터넷·전원 장애 때 로컬 장비 운전은 계속 가능한가?
- 알림 수신자와 장애 확인·AS 승인 책임자는 누구인가?
- 지불 의향 단위는 점포, 장비, 알림/분석 기능 중 무엇인가?

주요 위험은 제조사별 폐쇄형 인터페이스, 통신 음영·전원 장애, 오탐 알림, 원격 명령의 안전사고, 출동 절감 효과를 입증할 데이터 부족이다. 인터페이스가 열리지 않는 장비는 연동 불가 상태를 명시하고, 수기 점검/AS 기록을 대체 경로로 제공한다.
