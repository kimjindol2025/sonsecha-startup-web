# [기획서] 세차장 리뷰 관리

> **카테고리**: 08 마케팅·고객관리 (C급 · 확장)  
> **앱 ID**: `app-review-management`  
> **문서 상태**: 조사 초안 — 합성 리뷰/답글 승인 데모는 [구현 명세 v1.0](./03-review-management-implementation.md)을 따른다. 플랫폼 미연결/미게시.  
> **목적**: 매장 리뷰를 놓치지 않고 확인·분류·처리하며, 권한 있는 사람이 검토한 답변과 불만 해결 이력을 관리한다.

## 1. 범위와 운영 원칙

> 구현자는 이 초안만 보고 리뷰 API/스크래핑/게시 기능을 만들지 않는다. 합성 데이터와 차단 규칙은 [구현 명세 v1.0](./03-review-management-implementation.md)에 정의했다.

초기에는 각 매장의 네이버/구글 장소 URL과 리뷰 알림 확인, 내부 분류·티켓 이관, 답글 초안 승인 흐름을 제공한다. 플랫폼이 승인한 API와 권한이 확보된 경우에만 해당 리뷰 데이터를 연동한다. 네이버 공식 도움말은 스마트플레이스 주인 권한 계정의 답글 기능을 안내하며 브랜드채널 관리자는 지점 리뷰 답글을 일괄 작성할 수 없다고 명시한다. 그러므로 본사가 모든 지점 답글을 게시하는 흐름을 기본으로 삼지 않는다.

리뷰는 실제 방문 경험에 기반해 자발적으로 작성되도록 중립적으로 요청한다. 할인·포인트·무료 서비스 등을 리뷰 작성·수정·삭제의 대가로 제공하거나 긍정 리뷰만 유도하는 기능은 제공하지 않는다. 부정 리뷰에 대한 보상·삭제 요구, 자동 게시, 별점 조작을 금지한다.

## 2. 사용자와 MVP 기능

| 역할 | 주요 작업 |
| --- | --- |
| 지점 관리자 | 자기 지점 리뷰 확인, 사실 확인, 답글 최종 검토·게시 |
| 현장 담당자 | 내부 티켓에서 방문/장비/결제 이슈를 확인하고 조치 기록 |
| 본사 CX 담당 | 지점별 최소 집계 확인, 안전·개인정보·고위험 불만 이관, 템플릿 관리 |
| 플랫폼 연동 관리자 | 지점 권한/OAuth 관리, 연결·해제와 감사 기록 |

- 지점별 플랫폼/장소 URL, 마지막 확인 시각, 신규/미답변 상태
- 별점·날짜·채널과 리뷰 원문 링크; 원문 전문·프로필 사진 복제 저장은 기본 제외
- 내부 주제 태그(세차 품질/결제/장비·안전/직원/기타), 심각도, 담당자, 처리기한
- 답글 초안, 지점 권한자 승인, 게시 상태/시각, 수정 이력
- 불만은 내부 티켓으로 이관하고 고객 공개 답글과 개인 상담 기록을 분리
- 플랫폼의 리뷰 신고/미노출 이의/권리침해 요청 경로 링크

Google API 승인을 받지 못했거나 권한이 없는 경우 수동 확인 링크와 내부 체크리스트만 제공한다. 플랫폼 계정 비밀번호를 수집하거나 무단 스크래핑하지 않는다. Google 리뷰 답글 API 연동 시 사업주 승인, API 프로젝트 정책, OAuth와 저장 제한을 확인하고, 답글은 초안 → 권한자 명시적 확인 → 게시 버튼의 흐름을 따른다.

## 3. 불만 처리 흐름과 안전한 답변

새 리뷰 → 채널/지점·심각도 분류 → 현장 사실 확인 또는 본사 이관 → 필요 시 기존 고객지원 채널로 별도 상담 → 공개 답글 초안 검토 → 지점 권한자가 게시 → 조치/재발방지 이력 기록 순서다. 부상·차량 손상·결제 분쟁·개인정보 노출은 고위험 티켓으로 즉시 이관한다.

공개 답글에 고객 이름·전화번호, 차량번호, 결제 내역, 방문 시각, 내부 장비/사고 상세 등 개인정보나 확인되지 않은 사실을 적지 않는다. 비방·감정적 표현 대신 사과/확인 절차/정당한 상담 경로를 간결히 안내한다. 리뷰 작성자 연락처를 별도 채널로 찾아 연락하지 않는다.

## 4. 데이터·보존·권한

핵심 데이터는 `store`, `platform_location`, `review_reference`, `review_summary`, `topic_tag`, `severity`, `service_ticket`, `reply_draft`, `approval`, `platform_connection`, `audit_event`다. 본문을 저장해야 하는 경우 해당 API/플랫폼 정책의 수집 범위·보존 기간·삭제 요청을 준수한다. Google Business Profile API 정책은 API 콘텐츠를 제한된 목적에만 임시 저장하고 최대 30일 이내 보관, 보안 저장, 조작/집계 금지 등의 조건을 둔다. 이 제한 때문에 장기 분석 데이터는 원문 복제 대신 내부 태그·집계 또는 원문 링크를 검토하고, API 프로젝트에서 허용되는지 사전 확인한다.

리뷰 작성자 이름·프로필·연락처를 CRM의 고객 기록과 자동 결합하지 않는다. 지점별 최소 권한, 계정 연결/해제, 권한 회수, API 조회·초안·게시 승인 로그를 남긴다. 리뷰 원문·이미지의 저장과 장기 보관 필요성은 플랫폼 약관과 개인정보 근거 검토 전 확정하지 않는다.

## 5. 지표·검증 질문

지표 후보는 미답변/기한 초과율, 내부 첫 확인시간, 불만 티켓 해결시간, 동일 불만의 반복 유형, 채널별 신규 리뷰 수, 별점 추이(매장 맥락과 함께), 플랫폼 신고/이의 처리결과, 답글 승인·개인정보 노출 오류다. 별점 상승을 직원 보상이나 리뷰 요청 보상 기준으로 사용하지 않는다.

- 지점별 네이버 스마트플레이스 주인 권한/구글 관리자 권한은 누가 보유하고 쉽게 회수할 수 있는가?
- Google Business Profile API 프로젝트 승인·OAuth·콘텐츠 30일 저장 정책이 제품의 로그/분석 요구와 양립하는가?
- 네이버 사업주용 공식 리뷰 API나 별도 승인 파트너 연동이 현재 가능한가? 스크래핑 없이 어떤 기능까지 허용되는가?
- 본사 CX가 봐야 할 정보는 리뷰 링크·집계·심각도 중 무엇이며 개별 답글 승인 책임자는 누구인가?
- 안전·차량 파손·결제 이슈의 내부 사고/AS/고객지원 티켓으로 넘기는 시간과 담당자는?
- 모든 고객에게 중립 리뷰 링크를 요청할 수 있는 접점은 무엇인가? 인센티브나 긍정 리뷰만 유도하는 현재 관행은 없는가?
- 리뷰 원문·작성자 표기/프로필 정보를 내부에 보관해야 하는 이유와 보유기간은?

## 6. 단계별 실행안

| 단계 | 실행 | 완료 기준 |
| --- | --- | --- |
| 0. 권한/정책 조사 | 지점별 계정·API 권한, 플랫폼 정책, 저장/삭제 조건 확인 | 지점 동의·권한 회수·데이터 맵 승인 |
| 1. 수동 리뷰 운영 | 장소 링크, 확인 체크리스트, 불만 티켓, 답글 초안·승인 | 책임자·응답기한·불만 이관 흐름 검증 |
| 2. 허용된 API 연결 | 승인된 Google API 조회/답글 흐름을 지점별 시험; 네이버는 공식 경로 확인 후 판단 | 계정 승인·저장정책·명시적 게시 동의 확인 |
| 3. 다지점 운영 | 본사 집계·지점별 알림·위험 티켓 표준화 | 권한 최소화와 지점별 만족도/운영 부하 검토 |
