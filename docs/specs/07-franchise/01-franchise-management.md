# [기획서] 가맹점 통합관리

> **카테고리**: 07 본사·가맹점 서비스 (C급 · 확장)  
> **앱 ID**: `app-franchise-management`  
> **문서 상태**: 법령·제품사례 조사 기반 — 실제 계약·데이터 권한과 POS 연동 검증 필요  
> **목적**: 본사와 가맹점이 지점 운영, 장비·AS, 공지, 계약 일정의 필요한 정보를 권한에 따라 관리한다.

## 1. 서비스 범위와 원칙

가맹점과 본사가 함께 보는 지점 운영 시스템이다. 가맹사업법상 정보공개서 등록·계약서 기재 의무가 있다고 해서 모든 매장 매출·운영 데이터의 앱 공유가 자동으로 요구되는 것은 아니다. 각 기능과 필드는 계약, 실제 역할, 개인정보 처리 목적에 맞춰 합의해야 한다.

MVP는 지점 기준정보, 오픈/휴점/계약 메타데이터, 장비 목록과 미해결 AS, 공지·확인 이력, 권한이 확정된 매출 요약으로 제한한다. 회계 원장·고객 CRM·직원 출퇴근·POS 결제 원본 전체를 복제하지 않는다.

## 2. 사용자와 권한

| 역할 | 기본 접근 범위 |
| --- | --- |
| 본사 시스템 관리자 | 사용자·역할·지점별 권한 및 감사 기록 관리 |
| 본사 운영 담당 | 전체 또는 배정된 지역의 합의된 운영 필드 |
| 가맹점주 | 본인 지점의 운영 정보, 정정 요청, 공지·AS 확인 |
| 점장·직원 | 담당 지점의 업무·공지·점검 등 필요한 기능 |
| AS 협력사 | 배정된 티켓과 해당 장비 정보만 제한적으로 접근 |
| 회계·감사 담당 | 별도 승인된 필드의 읽기 전용 조회 |

권한은 지점뿐 아니라 매출·계약·AS·개인정보 필드 단위로 분리한다. 지역 관리자에게 타지역 계약/매출을 자동 허용하지 않는다. 조회·내보내기·수정·권한 변경 기록을 보존하고, 계약 종료 또는 담당 변경 때 접근을 회수한다.

## 3. MVP 기능과 흐름

- 지점 마스터: 운영자·주소·상태·담당자·오픈/휴점일·계약 상태/갱신 알림
- 운영 현황: 권한과 데이터 출처가 합의된 기간별 매출 요약, 장비 자산/상태, AS 현황
- 공지: 대상 지점·역할, 버전, 게시/확인 시각, 첨부 문서
- AS 요청: 장비·증상·사진·담당·진행 상태와 비용/완료 이력
- 자료/계약 메타데이터: 문서 유형·버전·유효기간·열람 권한·보관기간을 표시
- 오류 정정 요청과 본사/가맹점 승인·이의 기록

지점 등록 → 오픈 준비 체크리스트 → 운영자/권한 확정 → POS·장비 연동 또는 합의된 집계 입력 → 공지·AS 운영 → 계약 갱신/종료 시 데이터 내보내기와 권한 회수 순서로 제공한다.

## 4. 데이터 거버넌스와 법률 확인

핵심 데이터는 `franchise_group`, `store`, `store_operator`, `contract_metadata`, `store_metric`, `equipment`, `service_ticket`, `announcement`, `access_policy`, `audit_log`다. 매출 요약과 개인 식별 가능한 POS 거래는 분리하고, 집계·가명처리 등 최소 정보를 우선한다. 각 필드의 출처 시스템, 기간, 정정 이력을 보존한다.

운영 전 가맹계약/별도 약정에서 수집 필드·이용목적·본사 접근자·공유주기·오류 정정·보유/파기·종료 시 내보내기·시스템 비용을 검토한다. 고객·직원 개인정보가 플랫폼사에 위탁되는 경우 처리자/수탁자 역할과 문서·공개·감독 요건을 실제 구조에 맞춰 확인한다. 법률상 결론은 계약과 역할 검토 전 확정하지 않는다.

## 5. 지표와 위험

파일럿에서 측정할 지표는 지점 정보 완결·갱신률, POS 연동 성공/정정률, 공지 확인 시간, 오픈 준비 완료율, AS 최초 응답·해결 시간, 계약 갱신 누락, 데이터 오류 분쟁 수다. 매출 상승이나 운영 효율 개선은 기준선과 비교기간 없이 성과로 주장하지 않는다.

핵심 위험은 계약상 근거 없는 데이터 요구, 본사·점주 간 매출 접근 분쟁, POS 필드 오정합, 협력사 과다 접근, 직원/고객 개인정보 수집, 시스템 사용을 구매 강제와 결합하는 경우다. 권한 설계와 데이터 협의가 완료되지 않은 지점은 민감 기능을 비활성화한다.

## 6. 수익 가설과 검증 질문

**수익 가설**: 본사 구독료와 지점당 운영 계정 과금, 설치·POS/장비 연동 비용을 검토한다. 계약상 필수 시스템 여부와 지불 의향은 확인되지 않았다.

- 본사/가맹점/직영점/위탁운영점의 현재 구조와 계약상 디지털 시스템 조건은 무엇인가?
- 본사가 꼭 필요한 집계 필드와 점주가 공유를 원치 않는 필드는 무엇인가?
- POS API/CSV, 장비 AS·계약 관리 자료의 제공 주기·비용·오류 정정 주체는?
- 지역 관리자와 협력사의 업무상 최소 지점/필드 권한은 무엇인가?
- 공지 확인 증빙, 계약 종료 데이터 반출·삭제·보관 요구는 무엇인가?
- 매출, AS, 공지, 오픈 준비 중 첫 도입 가치를 만드는 흐름은 무엇인가?
- 운영 시스템 사용비용·도입 방식이 현재 계약에 어떻게 반영되어 있는가?
