# [기획서] 본사 AS 배차

> **카테고리**: 07 본사·가맹점 서비스 (C급 · 확장)  
> **앱 ID**: `app-hq-service-dispatch`  
> **문서 상태**: 현장서비스 제품·법령 조사 기반 — 실제 가맹/기사 운영구조 및 위치정보 적용 검토 필요  
> **목적**: 장비 AS 접수부터 분류, 기사 배정, 현장 보고, 완료 검토와 청구자료 정리까지 한 흐름으로 관리한다.

## 1. 대상 사용자와 범위

| 사용자 | 주요 작업 |
| --- | --- |
| 가맹점주·현장 접수자 | 장비·증상·긴급도·방문 가능시간 등록, 티켓 상태 확인 |
| 본사 디스패처 | 접수 검토, 안전/보증/긴급도 분류, 기사·일정 수동 배정, 완료 보고 검수 |
| 직영·협력 기사 | 배정 수락/거절, 이동·도착·작업 상태, 체크리스트·부품·시간·증빙 입력 |
| 부품 담당·회계 | 부품 출고/반납, 견적·추가 승인·청구자료 검토 및 내보내기 |

MVP는 접수·수동 배차·작업보고·청구자료 내보내기까지 제공한다. 결제와 세무 ERP는 대체하지 않으며, 기사 위치는 상시 추적하지 않는다.

## 2. 업무 흐름과 상태

1. 접수자가 매장·장비 ID/모델, 증상·오류코드, 안전 위험, 사진(선택), 연락·방문 가능 시간대를 제출한다.
2. 디스패처가 중복 여부, 우선순위, 보증, 유상 가능성, 원격 확인 항목을 검토한다.
3. 권역·기술·가용시간에 맞는 기사를 필터링해 배정하고, 기사가 수락 또는 거절한다.
4. 기사는 이동/도착/작업 상태를 바꾸고, 점검 항목·원인·조치·부품 SKU/수량·시간·작업 전후 사진·재방문 필요를 기록한다.
5. 본사는 보고서를 검토하고 보완·종결 처리한다. 견적 승인·청구는 별도 승인 후 회계 시스템용 자료로 내보낸다.

제안 상태: 신규 → 분류중 → 정보대기/안전조치대기/부품대기 → 배정대기 → 배정됨(수락/거절) → 방문예약 → 이동중(위치공유 선택) → 현장도착 → 작업중 → 기사완료보고 → 본사검토 → 청구대기 → 종결. 취소·재방문·작업불가·고객부재는 사유를 별도 남긴다.

## 3. MVP 기능·데이터

- 접수 필수 필드·긴급도 분류·안전 위험 확인 및 상태별 알림
- 기사 기술/권역/근무 가능시간 조회와 수동 배정·재배정
- 기사 모바일 상태 변경, 체크리스트, 사진/서명, 부품·작업시간·원인·조치 입력
- 고객/가맹점 방문시간·ETA 알림, 완료보고 검토·재작업 요청
- 보증/유상 근거, 견적·추가작업 승인, 청구자료 내보내기
- 오프라인 작업 저장·복구가 필요한지 파일럿으로 확인

데이터는 `service_ticket`, `store`, `equipment`, `symptom`, `severity`, `appointment_window`, `technician`, `skill`, `service_area`, `assignment`, `status_event`, `work_report`, `part_usage`, `estimate_approval`, `invoice_export`로 나눈다. 위치를 수집한다면 작업 ID·목적·수집 시각·정확도·만료 시각이 함께 있어야 한다.

## 4. 위치정보와 개인정보 보호

기본 위치 흐름은 기사 앱에서 이동 버튼을 누를 때 해당 작업의 위치 한 건만 공유하고, 목적은 당일 배차/ETA로 제한하는 안을 검증한다. 고객은 좌표·경로 대신 상태와 도착 예상시간만 확인한다. 위치 권한을 거부해도 수동 상태와 ETA로 정상 배차할 수 있어야 한다. 상시 백그라운드·근무 외 추적·장기 경로 기록은 MVP에 넣지 않는다.

기사 위치가 개인위치정보에 해당하는지, 서비스 운영자가 위치정보사업자/위치기반서비스사업자인지, 고용관계·동의·외부 지도 처리·위탁 관계가 어떠한지는 실제 기술/계약 구조를 토대로 별도 법률·노무 검토 후 확정한다. 목적에 필요한 최소 개인정보, 접근통제·접속기록·보유기간·삭제 및 기사/가맹점/협력사 권한 회수를 설계한다. 사진은 얼굴·차량번호 등 불필요 정보 최소화/마스킹을 검토한다.

## 5. 지표·위험·검증 질문

지표 후보: 접수 후 첫 응답시간, 배정까지 시간, 약속시간 준수/ETA 오차, 1회 수리완료율, 해결시간, 재방문율, 부품대기 시간, 완료보고 누락률, 청구 검토·정정 시간이다. 위치나 이동거리로 기사 생산성을 평가하는 지표는 초기 범위에서 제외한다.

주요 위험은 긴급도 판단 누락, 기술·권역 미스매치, 협력기사 정보 과다 공유, 위치정보의 불필요한 수집, 보증/유상 책임 분쟁, 오프라인 보고 손실이다.

- 현재 AS 접수 채널·건수·시간외 긴급건과 안전중단 판단자는 누구인가?
- 직영/협력기사 비중, 권역·자격·근무시간·배정 거부/재배정 규칙은 무엇인가?
- 제조사 보증·출장비·공임·부품비·추가 작업 승인·청구 기준 시스템은?
- 위치 공유가 실제 배차에 필요한가, 이동/도착 버튼과 ETA로 충분한가?
- 기사 앱 오프라인 기록, 사진, 고객 서명 중 필요한 현장 증빙은 무엇인가?
- 점주·본사·기사·협력사의 데이터 접근과 보관·종료 조건을 누가 결정하는가?

## 6. 단계별 실행안

| 단계 | 실행 | 완료 기준 |
| --- | --- | --- |
| 0. 업무 조사 | 최근 AS 사례, 역할, 긴급도·보증·청구 규칙 인터뷰 | 최소 상태·필수 데이터와 책임자 확정 |
| 1. 수동 배차 MVP | 접수·필터·배정·모바일 작업보고·완료검토 | 시간·보고 누락·재방문 기준선 측정 |
| 2. 선택 위치·연계 | 기사 선택형 단건 위치, ETA/부품/회계 내보내기 | 법무 검토와 현장 이용성 확인 |
| 3. 자동 배차 검토 | 권역·기술·일정 제약 기반 추천 | 자료 품질과 배차 개선 효과 검증 후 결정 |
