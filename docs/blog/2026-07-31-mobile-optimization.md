# 손세차장 창업 로드맵 모바일 최적화

- 날짜: 2026-07-31 KST
- 대상: `https://sonsecha.dclub.kr/`
- 구현 체크포인트: `871ef7f` (`fix(mobile): optimize startup roadmap layout`)

## 요청 해석

사용자는 운영 URL과 함께 “모바일 최적화”를 요청했다. 단순 진단이 아니라 운영 페이지의 모바일 사용성을 개선하고 실제 서비스 반영 여부까지 확인하는 작업으로 해석했다.

## 변경 내용

- 860px 이하에서 사라지던 주요 탐색 메뉴를 2단 모바일 헤더의 가로 탐색 메뉴로 복원했다.
- 520px 이하 히어로의 글자 크기, 여백, 일러스트 높이와 CTA 배치를 줄여 첫 화면 밀도를 개선했다.
- 모바일 단계 카드를 4열에서 3열 구조로 바꿔 제목과 설명의 유효 폭을 넓혔다.
- 단계 상세 버튼, 필터 버튼, 주요 CTA와 체크 영역을 터치하기 쉬운 크기로 조정했다.
- 후보지 입력창과 메모 입력창을 모바일에서 16px 이상으로 표시해 iOS 자동 확대 가능성을 줄였다.
- 서류 카드, 실무 체크리스트, 위험 안내, 최종 CTA와 푸터의 모바일 여백을 통일했다.
- 모바일 가로 넘침을 방지하고 긴 상세 콘텐츠가 카드 안에서 줄바꿈되도록 했다.

## 기존 변경 처리

작업 시작 시 `src/style.css`에는 이미 미커밋 변경 3줄이 있었다. 이 변경은 단계 체크박스 스타일이 후보지 텍스트 입력창까지 숨기던 선택자 범위를 좁히고, 후보지 입력창을 다시 보이게 하는 수정이었다. 모바일 입력 폼의 정상 동작과 직접 관련되어 있어 되돌리지 않고 이번 체크포인트에 함께 보존했다.

## 검증

- `npm run build`
  - Vite 프로덕션 빌드 성공
  - Sites 런타임용 정적 자산 3개 패키징 성공
- `git diff --check`
  - 공백 오류 없음
- Chrome Headless 화면 확인
  - 320×844 모바일: 가로 넘침 없이 헤더, 히어로, CTA 표시
  - 390×844 모바일: 모바일 탐색 메뉴와 히어로 정상 표시
  - 390px 긴 화면: 12단계 카드가 3열 모바일 구조로 표시
  - 1440×900 데스크톱: 기존 2열 히어로와 데스크톱 메뉴 유지
- 동적 DOM 확인
  - 단계 카드 12개
  - 세부 체크 항목 175개
  - 후보지 입력 폼 1개
- 운영 반영 확인
  - 운영 HTML이 새 CSS `/assets/index-BQE2JTxQ.css`와 JS `/assets/index-4Bynfd3E.js`를 제공
  - `https://sonsecha.dclub.kr/`의 390×844 운영 화면을 다시 캡처해 로컬 결과와 일치함을 확인

## 시행착오와 교정

- 샌드박스에서 Vite의 로컬 포트 바인딩과 Chrome Headless 실행이 제한됐다. 승인된 범위로만 다시 실행해 로컬 화면을 검증했다.
- 해시 URL로 특정 섹션을 캡처할 때 부드러운 스크롤 때문에 중간 프레임이 찍혔다. 최종 검증은 상단부터 이어지는 긴 모바일 캡처로 바꿔 카드 전체 흐름을 확인했다.
- 처음부터 있던 미커밋 CSS를 새 변경으로 오인해 덮어쓰지 않도록 먼저 `git diff`를 확인했다. 선택자 수정은 후보지 입력창 표시 버그와 관련된 변경임을 확인한 뒤 유지했다.

## 남은 위험과 다음 작업

- 실제 iPhone Safari와 Android Chrome 기기에서의 수동 터치 테스트는 하지 않았다.
- Lighthouse나 Web Vitals 자동 측정 도구는 이 저장소에 설치되어 있지 않아 수행하지 않았다.
- 다음 작업자는 실기기에서 상세 단계 열기, 체크 저장, 메모 입력, 후보지 주소 입력과 페이지 재방문 후 로컬 저장 복원을 우선 확인해야 한다.
