# 손세차장 로그인 제외 진행판과 배포 경계

기록일: 2026년 11월 7일 한국시간. Kim의 PRD v3 검토 뒤 “코딩 시작 로그인은 이번에는 패스”에 따라 로컬 진행판을 구현했고, 이어 커밋·배포 요청을 받았다.

## 목적과 실제 변경

첫 범위는 사업·후보지 등록, 검토 의뢰, 담당자 배정, 수동 검토·공개 답변, 결과 재조회와 재문의다. 기존 계산기·상품·상담의 사업 연결과 실제 로그인은 제외했다.

`workspace-store.mjs`에 별도 SQLite 자료와 소유·배정 권한, 제출 중복 방지, 초안 버전 충돌, 공개·내부 기록 분리, 답변 정정·재문의 이력을 구현했다. `workspace-preview.mjs`는 로컬 시험 서버이며 `server.mjs`에는 역할 선택이나 새 공개 접수 API를 추가하지 않았다. `workspace.html`, `src/workspace.js`, `src/workspace.css`에서 고객·책임자·담당자 흐름을 확인한다.

기존 소스에는 이전 검증·수정이 미커밋으로 남아 있었다. 원본 서비스의 파일을 보존하고 별도 worktree를 만든 뒤, 기존 수정은 `02fb9d1` (`fix(site): preserve verified access, image and mobile fixes`)에 구분해 기록했다. 새 진행판은 후속 `feat(workspace): add isolated candidate review workflow` 체크포인트로 기록한다.

## 실패와 교정

처음 격리 빌드 사본에서 README를 빠뜨렸다. `src/main.js`가 README를 원문으로 가져오기 때문에 빌드에 실패했고, 사본에 해당 입력을 포함한 뒤 통과했다. 의존성을 복사할 때 실행 파일 심볼릭 링크가 일반 파일로 바뀌어 Vite 실행 경로가 깨진 일도 있었다. 작업 사본의 실행 링크를 복구했으며 원본 의존성은 변경하지 않았다.

브라우저 시험에서는 실제 첫 상품이 품절일 수 있었고, 같은 주소 이동이 새 문서 로드가 아닐 수 있었다. 시험 대상을 실제 동작 가능한 상품으로 고르고 문서 로드를 구분했다. 새 진행판 대화창의 Tab 이동은 마지막 요소 뒤 본문으로 빠지는 사례가 있어 순환을 명시하고 Esc·저장 성공 후 원래 버튼으로 초점이 돌아오는지도 검사했다.

이번 진행판과 무관한 기존 변경을 한 번의 신규 기능 커밋에 섞지 않았다. 실제 고객 자료와 원본 `dist`도 시험에 쓰지 않았다.

## 검증

Vite 빌드·패키징, 신규 서버 시험 20개, 새 진행판 브라우저 검증 10항목, 기존 기능 회귀 명령 6개가 통과했다. 신규 시험은 응답 유실 뒤 재전송, 다른 고객·담당자 접근, 재배정 이후 파일 요청, 금지 상태 전이, 내부 메모 분리, 동시 저장·답변 중복·원자적 복구를 포함한다.

브라우저에서는 합성 자료로 등록→의뢰→배정→검토→답변→재문의를 실행했고, 저장 통신 실패와 오래된 초안의 충돌, 입력 유지·최신 버전 확인, 390px 화면과 키보드 조작을 확인했다. 실제 로그아웃·재로그인은 구현하지 않았으므로 그 항목은 통과로 쓰지 않았다. 상세 증거는 `docs/implementation/prd-v3/`의 검수표와 시험 결과를 참조한다.

## 커밋·배포 요청에서 확인한 차이

Gogs `master`는 `f648925`였고, 이 개발 사본의 최초 기준 `3761f10` 뒤에 다른 작업 8개가 있었다. 원격 master를 강제 갱신하거나 기존 작업을 덮어쓰지 않는다. 이번 체크포인트는 `feat/prd-v3-review-workspace` 브랜치로 보존한다.

서버 73의 공유 post-receive는 master 브랜치만 처리한다는 조건을 읽기 전용으로 확인했다. 손세차장의 DNS Manager 목록·이력 조회 주소는 이번 확인에서 404를 반환했다. 이것을 배포 자동화 자체가 없다는 뜻으로 해석하지 않는다. 공유 hook·watcher·nginx·PM2 설정은 변경하지 않았다.

현재 시험 서버는 명시적인 시험 실행 조건이 필요하고 `NODE_ENV=production`에서는 시작하지 않는다. 시험 역할 전환을 공개하면 방문자가 담당자도 선택할 수 있다. 따라서 개발본의 운영 차단을 해제해 공개하는 배포는 하지 않는다. 배포 형태는 실제 접수 없는 방문자별 브라우저 체험판과, 별도의 고객 자료 보호 경계를 연결한 실제 접수 방식 중 확인이 필요해 선택을 요청했다.

## 다음 작업자의 시작점

현재 코드는 개발본이며 원격 브랜치 보존과 실제 사이트 배포는 별개다. 배포 형태가 결정되면 그 선택에 맞는 공개용 변경을 구현·검증한다. 원격 master의 후속 작업도 따로 확인하고, 기본 브랜치를 강제 push하지 않는다. 정적 파일 반영으로 충분한지 먼저 판단하고, 기존 프로세스 재시작이 필요하면 `/home/kim/AGENTS.md`에 따라 정확한 대상·작업을 먼저 알리고 별도 승인을 받는다.

외부 연락·실제 고객 자료 이전·운영 DB 변경은 실행하지 않았다. 이 기록의 시험 결과를 실제 인증이나 실제 고객 접수 검수로 확대하지 않는다.
