# 손세차장 사업계획서 — 질문을 실제 실행 문서로 정리하다

- 기록일: 2026-08-02 KST
- 대상: `sonsecha-startup-web`
- 계획 체크포인트: `feat(plan): add guided business plan service`

## 요청을 어떻게 이해했는가

처음에는 사용자가 자유롭게 내용을 쓰는 사업계획서 편집기를 떠올리기 쉬웠다. 그러나 kim의
의도는 빈 양식을 주는 것이 아니었다. 대한이엔지가 창업 준비에 필요한 질문과 조사 순서를
제공하고, 사용자가 답한 사실을 하나의 사업계획서로 정리해 주는 서비스였다.

따라서 다음 흐름으로 구현했다.

```text
자금·지역·사업 형태·평수·베이·일정 입력
→ 창업예산과 월 운영 가정 입력
→ 상권·통계·지원·정책자금 공식 자료 확인
→ 기존 후보지 12단계 기록 연결
→ 전체 사업계획서 자동 정리
→ 복사 또는 인쇄·PDF
```

## 구현 내용

- 상단에 `사업계획서` 탭과 `#plan` 화면을 추가했다.
- 사업계획서는 `sonsecha-business-plans-v1` 키에 브라우저 로컬 저장한다.
- 여러 계획서를 만들고 전환해도 데이터가 서로 섞이지 않는다.
- 사용자가 후보지를 직접 선택하고 불러오기 버튼을 눌렀을 때만 주소·형태·베이 정보를
  복사한다.
- 임대, 인허가, 바닥·배수, 폐수처리, 전기·수도·소방, 장비, 인테리어, 초도용품,
  보험, 홍보, 운전자금, 예비비를 포함한 14개 창업예산 항목을 제공한다.
- 객단가·하루 차량·월 영업일과 8개 월 운영비로 단순 매출·잔액·손익분기 차량 수를
  계산한다.
- 상권정보시스템, 통계청 SGIS, K-Startup, 소상공인정책자금 공식 확인 경로를 제공한다.
- 입력값은 사업 개요, 일정, 예산, 자금 조달, 매출·운영비, 시장 조사, 후보지 12단계,
  공식 자료, 위험과 다음 행동, 보완항목을 포함한 전체 문서로 즉시 정리된다.
- `내용 복사`와 `인쇄·PDF`에도 요약이 아니라 전체 내용이 들어간다.

## 판단 경계

이 기능은 사용자가 입력한 사실과 가정을 조직한다. 지역명만으로 상권성을 판정하거나,
허가 가능성·대출 승인·지원사업 선정·수익을 확정하지 않는다. 작성하지 않은 사실은
만들지 않고 `확인 필요`로 남긴다. 예시 금액도 사용자가 버튼을 눌렀을 때만 들어가며
실제 견적이나 평균 창업비로 표현하지 않는다.

로컬 후보지 기록은 자동 서버 동기화하지 않는다. 기존 후보지 저장 키와 데이터 구조도
변경하지 않았다.

## 잘못된 점과 사용자 교정

1차 출력은 입력 항목을 많이 받으면서도 마지막 결과는 핵심 요약에 가까웠다. kim이
“전체 내용을 정리해주는 기능도 있어?”라고 묻지 않았다면, 입력과 결과물의 깊이가 맞지
않는 상태로 남을 수 있었다. 이후 전체 문서 11개 장으로 확장했다.

확장 후 첫 브라우저 테스트에서는 보완항목 목록에 `작성자·예비 대표`가 나오지 않아
실패했다. 출력 문제가 아니라 필수 보완 필드 목록에서 작성자를 빠뜨린 구현 누락이었다.
해당 필드를 추가하고 테스트 전체를 다시 실행했다.

다음 작업자는 질문 입력 개수만 보고 서비스가 완성됐다고 판단하면 안 된다. 사용자가
마지막에 받는 문서가 그 질문들을 실제로 모두 소비하는지 확인해야 한다.
