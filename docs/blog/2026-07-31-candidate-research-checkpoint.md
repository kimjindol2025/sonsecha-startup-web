# 손세차장 후보지별 체크리스트와 상세 조사 체크포인트

- 날짜: 2026-07-31 KST
- 대상: `https://sonsecha.dclub.kr/`
- 계획 체크포인트: 이 기록과 구현을 함께 담는 `feat(checklist)` 커밋

## 요청 해석

사용자는 모바일 화면의 실제 가독성을 다시 확인한 뒤, 한 주소만 기록하는 방식이 아니라 여러 후보지를 추가하고 주소마다 별도의 체크리스트를 제공해 달라고 요청했다. 이어서 12단계의 각 항목을 인터넷 조사로 자세히 보강하라고 지시했다. 따라서 이번 작업은 모바일 외형 수정에 그치지 않고, 후보지 비교 도구와 공식 자료 기반 실무 안내를 한 번에 완성하는 작업으로 해석했다.

## 변경 내용

- 후보지 탭과 `+ 후보지 추가` 버튼을 만들고 후보지 이름·주소·종합 판정을 관리하도록 했다.
- 후보지마다 12단계 완료 여부, 상세 체크 항목, 메모, 단계별 판정(미검토·가능·조건부·불가)을 독립 저장한다.
- 후보지 전환·삭제·현재 후보지 초기화를 구현하고 최소 한 후보지는 항상 남도록 했다.
- 기존 단일 후보지, 단계 진행률, 상세 체크와 메모의 로컬 저장 데이터를 새 다중 후보지 형식으로 자동 이전한다.
- 12단계 안내에 토지이음, 국가법령정보센터, 정부24, 국세청, KOSHA 등 공식 확인 경로와 현장 질문·확인 서류·완료 증빙을 추가했다.
- 폐수배출시설 가동시작 신고와 사업자등록 기한 표현을 법령 취지에 맞게 보정했다.
- 영업배상책임보험을 일률적 법정 의무로 표현하지 않고 실제 증권의 차량손상 보장·면책을 확인하도록 교정했다.
- 조사 본문의 Markdown 링크를 실제 클릭 가능한 출처 링크로 렌더링했다.
- 모바일에서 후보지 탭은 가로로 탐색하고 입력·선택·추가·삭제 버튼은 48px 높이와 16px 글꼴을 사용하도록 했다.

## 왜 중요한가

손세차장 가능 여부는 같은 사업자라도 주소마다 용도지역, 건축물 용도, 배수 경로, 진출입 조건과 환경부서 판단이 달라진다. 후보지별 기록을 분리하지 않으면 한 주소의 확인 결과가 다른 주소에 섞여 계약 판단을 잘못할 수 있다. 공식 확인 경로와 완료 증빙을 단계별로 붙인 이유도 온라인 정보만으로 허가 가능하다고 단정하지 않고 관할 부서 협의 결과를 남기기 위해서다.

## 검증

- `npm run build`: Vite 프로덕션 빌드와 정적 자산 패키징 성공
- `git diff --check`: 공백 오류 없음
- Chrome Headless 모바일 화면: 가로 넘침 없음, 후보지 패널과 단계 판정의 가독성 확인
- 후보지 기능 자동 확인: A/B 후보지의 주소, 단계 완료, 상세 체크, 단계 판정이 서로 섞이지 않고 복원됨
- 이전 형식 마이그레이션 확인: 기존 후보지 이름·주소·단계·상세 체크·메모가 새 저장 구조에 유지됨
- 운영 재시작: PM2 `sonsecha-startup-web` 재시작 후 로컬 포트와 공개 도메인 모두 HTTP 200
- 운영 번들 확인: `sonsecha-candidates-v2`, 후보지 추가, 공식 출처와 사업자등록 20일 안내 포함
- PM2 오류 로그: 오류 없음

## 시행착오와 사용자 교정

- 첫 모바일 최적화 체크포인트 뒤에도 사용자는 모바일 기준 가독성이 부족하다고 지적했다. 이번에는 후보지 도구까지 실제 모바일 폭에서 다시 확인하고 입력 컨트롤의 글자와 높이를 명시적으로 고정했다.
- 처음 구조는 후보지 한 곳만 저장했다. 사용자가 “주소 별 체크리스트 개별 제공”을 요청해 저장 단위를 주소 후보지별로 완전히 분리했다.
- 후보지 이름과 주소 입력만으로는 비교 흐름이 부족했다. 사용자가 “후보지 추가는? 추가버튼”이라고 교정해 명시적 추가 버튼과 후보지 탭을 구현했다.
- 단순 항목 나열로는 계약 전 판단 근거가 부족했다. 사용자의 “각 항목 인터넷 조사 자세히” 지시에 따라 공식 확인 경로, 부서 질문, 제출·확인 서류와 완료 증빙을 각 단계에 추가했다.
- 로컬 저장 이전 로직은 처음에 메모리에서만 변환되고 새 키에 즉시 기록되지 않았다. 로드 직후 새 구조를 저장하도록 수정하고 구형 데이터 샘플로 재검증했다.
- 데스크톱 앱 자동화 런타임이 준비되지 않아 Chrome Headless와 CDP 기반 기능 테스트로 대체했다. 실제 iPhone·Android 기기 테스트는 수행하지 않았다.

## 다음 작업자가 알아야 할 점

- 저장 데이터는 브라우저 `localStorage`의 `sonsecha-candidates-v2`에 있으며 서버 동기화 기능은 없다.
- 상세 체크 ID는 단계와 항목 순서를 기반으로 하므로 README의 기존 항목 순서를 바꾸면 저장된 체크와 연결이 달라질 수 있다. 기존 항목은 가능한 한 순서를 유지하고 새 항목을 뒤에 추가해야 한다.
- 공식 링크와 법령은 변경될 수 있으므로 실제 계약 전에는 관할 시·군·구 건축·환경·도로 부서의 서면 또는 민원 회신을 최종 근거로 삼아야 한다.
- 다음 우선순위는 실기기 Safari/Chrome에서 후보지 추가·전환·삭제, 페이지 재방문 복원과 긴 조사 본문의 터치 스크롤을 확인하는 것이다.
