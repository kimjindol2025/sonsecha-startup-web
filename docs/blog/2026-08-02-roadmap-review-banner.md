## 사용자 요청을 해석한 방식

사용자는 창업 12단계 사이에 배치된 상품 배너 3개 중 가운데 배너를 상품 안내가 아니라 `후보지 검토 요청 · 빅워시 문의` 진입점으로 바꾸라고 했다. 여기서 “가운데”는 제품몰의 상품 카드가 아니라 7단계 뒤에 있던 고압세척기 로드맵 배너를 뜻한다.

새 문의 양식을 만들지 않고, 이미 후보지별 1~12단계 체크·판정·메모·사진을 선택해 보내는 `후보지 검토 요청서` 작성 흐름에 연결했다. 첫 번째 폐수처리기 배너와 세 번째 콤프레셔 배너는 그대로 유지했다.

## 변경 내용

- 가운데 `<a href="#shop">` 상품 링크를 `후보지 검토 요청` 버튼으로 교체했다.
- 고정형 요청서 버튼과 새 로드맵 배너에 `data-consultation-request`를 부여했다.
- 상담 모듈은 단일 `#consultationRequestButton` 대신 모든 공용 트리거를 같은 `startCreate()`에 연결한다.
- 배너 문구는 `후보지 검토 요청`, `1~12단계 체크·판정·메모를 선택해 빅워시에 검토를 요청하세요.`, `빅워시 문의 →`로 구성했다.
- 운영 콘텐츠 API의 구형 값을 피하기 위해 `reviewBannerTitle`, `reviewBannerDescription`, `reviewBannerCta` 전용 콘텐츠 키를 추가했다.
- 앵커 전용이던 배너 레이아웃 CSS를 앵커와 버튼 모두 같은 모양으로 표시하도록 확장했다.
- built-in imagegen으로 세차장 건물, 위치 핀, 체크리스트를 조합한 간단한 3D 일러스트를 생성했다.
- 생성 원본 1632×964 PNG를 760×449, 284KB로 줄여 `public/roadmap-review-banner.png`에 저장했다.

## 왜 중요했는가

기존 배너는 12단계 절차 중간에서 사용자를 제품몰로 보냈다. 변경 후에는 후보지의 단계별 기록이 쌓이는 시점에 같은 기록을 가지고 빅워시 검토 요청서를 바로 만들 수 있다. 요청서가 다시 질문해야 할 내용을 줄이는 것이 기존 기획 의도다.

전용 콘텐츠 키 분리는 운영 반영 안정성에도 중요하다. 실행 중인 서버가 아직 구형 콘텐츠 기본값을 반환해도 새 클라이언트의 검토 배너 문구가 고압세척기 문구로 덮이지 않는다. 향후 서버가 재시작되면 관리자 콘텐츠 필드에도 새 전용 키가 정식으로 나타난다.

## 실수와 사용자 교정

### 운영 API가 새 문구를 다시 덮어쓴 문제

처음에는 기존 `banner2Title/Description/Cta` 콘텐츠 키를 그대로 재사용했다. 소스와 운영 빌드는 새 문구였지만, 브라우저가 `/api/content`에서 받은 구형 고압세척기 값을 같은 키에 적용하면서 화면은 다시 고압세척기로 보였다. 사용자가 운영 화면 스크린샷으로 “아직도 고압으로 나온다”고 지적했고 그 지적이 맞았다.

재시작만으로 넘기지 않고 검토 요청 전용 키로 분리했다. 다음 Codex는 정적 HTML 기본값만 확인하지 말고, API 로딩이 끝난 최종 DOM까지 검사해야 한다.

### 임시 도식 이미지의 완성도가 낮았던 문제

첫 시안은 이미지 칸에 `01`, `12`, 체크 표시를 CSS 도형으로 넣었다. 기능 의미는 있었지만 사용자가 보기에는 임시 개발 도식처럼 보였고 배너 완성도가 낮았다. 사용자가 “배너 이미지가 별로”라고 바로잡은 뒤 세차장 후보지 검토를 직접 나타내는 전용 이미지를 생성했다.

### 브라우저 검증 대기 조건

요청서 모달은 먼저 열리고 내부 폼은 비동기로 렌더링된다. 모달 클래스만 확인한 직후 폼을 읽어 첫 검증이 실패했다. 폼 생성까지 기다리도록 고쳤다. 이미지도 `loading="lazy"`라 화면 밖에서는 로딩되지 않았는데, 이를 실패로 읽지 않도록 배너를 뷰포트로 스크롤한 뒤 자연 폭을 검사했다.

## 남은 위험과 다음 작업

- `roadmap-review-banner.png`는 장기 캐시가 적용되는 고정 URL이다. 앞으로 이미지를 다시 바꾸면 새 버전 파일명으로 교체하는 편이 안전하다.
- 실행 중 서버는 아직 구형 콘텐츠 필드 정의를 메모리에 가지고 있다. 현재 화면은 전용 클라이언트 기본 키 덕분에 정상이나, 관리자에서 새 배너 문구를 편집하려면 다음 승인된 단일 PM2 재시작 뒤 필드가 나타난다.
- Gogs 푸시 후에도 운영 `dist`는 Git 제외이므로 소스 체크아웃만으로 운영 반영 상태를 판단하지 않는다. 반드시 빌드와 실제 운영 DOM을 함께 확인한다.
