# 제품몰·장바구니·간이견적서 체크포인트

- 날짜: 2026-07-31 KST
- 운영 주소: `https://sonsecha.dclub.kr/#shop`
- 계획 체크포인트: 이 기록과 구현을 함께 담는 `feat(shop)` 커밋

## 요청 해석

사용자는 기존 손세차장 창업 안내 사이트에 회사 판매 제품을 올릴 수 있는 탭을 만들고, 품목별 카테고리와 장바구니를 갖춘 실제 쇼핑몰 형태로 구성하라고 요청했다. 상품 등록은 나중에 진행한다고 명시했다. 후속 요청에서는 장바구니 상품을 견적서 형태의 폼으로 볼 수 있게 해 달라고 했다.

현재 프로젝트는 Vite 정적 사이트이며 주문 서버, 관리자 인증, 이미지 저장소와 PG 결제가 없다. 따라서 이번 체크포인트는 상품 데이터만 추후 넣으면 작동하는 공개 카탈로그, 브라우저 장바구니, 전화 견적 연결과 인쇄 가능한 간이견적서를 구현하는 범위로 정했다.

## 구현 내용

### 제품몰

- 상단 메뉴와 본문에 `제품몰` 탭을 추가했다.
- 전체 상품, 세차 케미컬, 세차 도구, 장비·부품, 안전·관리용품 카테고리를 만들었다.
- 상품명 검색과 추천순·상품명순·가격순 정렬을 구현했다.
- 상품 카드에 이미지, 배지, 카테고리, 상품명, 설명, 가격, 재고와 담기 버튼을 표시할 수 있다.
- 상품 데이터는 `src/products.js`에서 관리하며 현재 공개 배열은 사용자의 지시대로 비어 있다.
- 상품이 없을 때 판매 준비 중 안내와 제품 상담 전화가 표시된다.

### 장바구니

- 상단과 제품몰 헤더에 장바구니 수량 배지를 추가했다.
- 상품 담기, 삭제, 1~99개 수량 변경과 예상 합계를 구현했다.
- 가격 미정 상품은 `가격 문의`로 표시하고 금액 합계에는 포함하지 않는다.
- 장바구니는 `localStorage`의 `sonsecha-shop-cart-v1`에 저장한다.
- 문의 상품 목록 복사와 `031-1688-7759` 전화 주문·견적 문의를 제공한다.

### 간이견적서

- 장바구니가 비어 있지 않을 때 `견적서 작성` 버튼을 활성화한다.
- 견적번호, 작성일, 14일 유효기간과 상품명·단가·수량·금액·상품 합계를 자동 생성한다.
- 받는 회사·상호, 담당자, 연락처, 이메일, 배송·설치 주소와 요청사항 입력 폼을 제공한다.
- 공급자 영역에는 대표이사 김진돌, 사업자등록번호 127-38-49368, 회사 주소와 문의전화를 넣었다.
- 고객 입력은 `localStorage`의 `sonsecha-quote-form-v1`에 자동 저장하고 재방문 시 복원한다.
- 견적 내용 복사와 브라우저 인쇄·PDF 저장을 제공한다.
- 배송비, 설치비, 부가세 적용과 재고는 최종 상담에서 확정된다는 문구를 명시했다.

## 사용자 교정과 판단 기록

- 처음에는 공개 카탈로그와 직접 관리하는 관리자 페이지 중 선택이 필요하다고 판단해 질문했다. 사용자는 실제 쇼핑몰 형태와 장바구니를 원하되 상품 등록은 추후라고 범위를 확정했다. 이에 관리자·서버 기능을 억지로 추가하지 않고 상품 데이터 파일과 구매 UI 기반부터 만들었다.
- 첫 제품몰 반영은 장바구니와 전화 견적 문의까지였다. 사용자가 장바구니 내용을 견적서 폼으로 보여 달라고 요청해 고객정보 입력, 자동 품목표, 공급자 정보, 복사와 PDF 출력까지 확장했다.
- 실제 상품이 없는 상태에서는 장바구니와 견적서 경로를 검증할 수 없었다. 임시 상품을 코드에 넣어 브라우저 자동 검증한 뒤 반드시 제거하고 다시 빌드했다. 다음 작업자도 상품 데이터가 비어 있다는 이유로 동작 검증을 생략하지 말아야 한다.

## 남은 위험과 다음 작업

- 공개 상품은 아직 0개다. 실제 상품명, 가격, 사진, 재고와 카테고리를 사용자에게 받아 `src/products.js`에 등록해야 한다.
- 현재 장바구니와 견적 정보는 각 이용자의 브라우저에만 저장된다. 다른 기기 공유, 회사 수신, 주문 이력과 재고 차감 기능은 없다.
- 온라인 결제와 서버 주문 접수에는 PG 계약, 주문 API, 관리자 인증, 개인정보 처리와 환불·배송 정책이 필요하다.
- 현재 견적서는 자동 생성되는 간이견적서다. VAT 포함 여부, 배송·설치비, 할인과 공식 직인·서명 정책이 확정되면 계산 구조와 문구를 교정해야 한다.
- 고객 입력값을 외부로 전송하지는 않지만 공용 기기에는 남을 수 있다. 서버 주문 기능을 만들 때 개인정보 수집 동의, 보관기간과 파기 절차를 함께 구현해야 한다.
- 상품 이미지 권장 규격과 등록 형식은 `docs/product-catalog.md`를 따른다.

## 후속 교정: 제품몰 상위 탭 분리

첫 구현은 `제품몰` 링크가 있었지만 상품 섹션 자체가 창업가이드의 핵심 원칙 바로 뒤에 배치되어 있었다. 사용자는 “탭으로 분리하지? 처음부터 상품이야?”라고 지적했다. 제품몰을 링크만 있는 같은 스크롤 섹션으로 해석한 것이 잘못이었다.

- 기본 주소에서는 기존 창업가이드만 보이고 제품몰 섹션은 숨기도록 했다.
- 상단에 `창업가이드`와 `제품몰` 상위 탭을 만들고 활성 화면을 명확히 표시했다.
- `#shop`으로 이동하거나 직접 접속할 때는 창업가이드 섹션을 모두 숨기고 제품몰 전용 화면만 표시한다.
- 창업가이드로 돌아오면 제품몰과 장바구니 메뉴를 숨기고 절차·서류·실무·주의사항 하위 메뉴를 다시 표시한다.
- 모바일 390px에서 기본 진입, 양방향 탭 전환과 `#shop` 직접 진입을 검증했다. 각 화면의 비대상 섹션은 `display: none`이고 가로 넘침은 없었다.

다음 작업자는 사용자가 말한 “탭”을 같은 페이지의 단순 앵커 링크로 축소 해석하지 말고, 각 업무 화면이 서로 섞이지 않는 상위 뷰 전환으로 구현해야 한다.

## 후속 구현: k002.com 샘플 상품

사용자는 `k002.com`이 회사의 기존 쇼핑몰이라고 알려주고, 공개 상품을 가져와 샘플로 넣어보라고 요청했다. `agent-reach`의 일반 웹페이지 경로로 기존 공식몰 메인 상품명·가격·이미지·상세주소를 읽고 이미지 응답도 확인했다.

- `k002.com` 메인에 공개된 진공청소기 모터·카본브러쉬, 세차솔대, 압력게이지, 필터 하우징, 랜스형 인젝터와 XMTA 고압펌프 등 8개를 `src/products.js`에 등록했다.
- 각 카드에 기존 공식몰 상품 이미지, 공개 가격과 `공식몰 상세` 링크를 표시했다.
- 제품몰 상단에 `k002.com 바로가기`를 추가했다.
- 새 제품몰 장바구니와 간이견적서 기능도 그대로 사용할 수 있도록 샘플 상품 ID와 가격을 연결했다.
- 모바일 390px에서 상품 카드 8개, 공식몰 상세 링크 8개, 원격 이미지 8개 로드를 확인했다.
- 추천순 첫 상품 XMTA 3.5G 22 고압펌프 550,000원을 장바구니와 견적서에 담아 상품명·수량·합계와 브라우저 저장을 확인했다.
- PM2 재시작 후 공개 번들에 `k002-` 상품 8개와 공식몰 상세 기능이 포함됐고 오류 로그가 없음을 확인했다.

중요한 제한은 이 상품 목록이 `k002.com`을 실시간으로 읽는 동기화 기능이 아니라 2026-07-31 KST 공개 정보를 복사한 정적 샘플이라는 점이다. 기존몰의 가격·품절·상품명이 바뀌면 `src/products.js`도 별도로 교정해야 한다. 상세 구매는 기존몰, 여러 장비 묶음 견적은 새 장바구니·견적서라는 역할 구분을 유지한다.

## 후속 구현: 12단계 사이 제품몰 배너

사용자는 12단계 목차 중 3·7·10번 사이에 이미지가 포함된 쇼핑몰 연결 배너를 요청했다. 배너는 각각 해당 단계 카드 바로 다음에 배치했다.

- 3번 조건부 임대차계약 뒤: XMTA 고압펌프 이미지와 장비 예산 확인 배너
- 7번 배수설비·도로 신고 뒤: 필터 하우징 이미지와 설비 부품 점검 배너
- 10번 폐수시설 가동 절차 뒤: 진공청소기 카본브러쉬 이미지와 개업 예비부품 배너
- 세 배너 모두 `#shop`으로 연결해 현재 문서에서 제품몰 상위 탭으로 전환한다.
- 단계 필터가 전체가 아닐 때는 `검토`, `인허가`, `개업`에 대응하는 배너만 보이도록 했다.
- 모바일 390px에서 배너 3개가 각각 3·7·10번 다음에 있는지, 이미지 3개 로드, 가로 넘침 없음과 제품몰 전환을 확인했다.

배너 이미지는 기존 `k002.com` 공개 상품 이미지를 원격으로 사용한다. 기존몰 이미지 경로가 바뀌면 배너도 깨질 수 있으므로 상품 데이터 점검 시 배너 이미지도 함께 확인해야 한다.

### 배너 상품 교체

사용자가 배너별 상품을 다시 지정해 1번은 폐수처리기, 2번은 고압세척기, 3번은 콤프레셔로 교체했다. 폐수처리기와 고압세척기는 사용자가 제공한 `k002.com` 이미지 주소를 그대로 사용했고 두 파일 모두 HTTP 200과 JPEG 응답을 확인했다. 콤프레셔는 특정 판매 제품이 아닌 일반 사진을 요청해 Wikimedia Commons의 소형 산업용 콤프레셔 사진을 사용했다. 해당 사진은 RussianTrooper가 공개한 CC0 1.0 자료다.

- 폐수처리기 이미지: `https://www.k002.com/mall/shop_image/202004/2_sum_500%282%29_1545034089%282%29.jpg`
- 고압세척기 이미지: `https://www.k002.com/mall/shop_image/202004/sum_500.jpg`
- 콤프레셔 이미지·라이선스: `https://commons.wikimedia.org/wiki/File:Compressorstation.jpg` (CC0 1.0)

### K002 세차장 카테고리 전체 상품 등록

K002의 `ps_ctid=01000000` 카테고리 원문을 기준으로 상품 12개의 상품명·판매가·이미지·상세 링크를 제품몰에 추가했다. 기존 샘플 8개는 유지해 전체 상품은 20개가 되었다. 원문에서 품절 아이콘이 표시된 `하부세차기 (바닥매립형)`은 카드를 노출하되 장바구니 버튼을 비활성화했다. 나머지 11개는 가격을 포함해 견적 장바구니에 담을 수 있다.

제품몰의 `OFFICIAL SHOP` 버튼도 K002 메인이 아닌 해당 세차장 카테고리로 바로 연결하도록 변경했다.

### 비밀번호 관리자 모드와 상품 대시보드

`/admin.html`에 비밀번호만 입력하는 관리자 로그인을 추가했다. 클라이언트 코드에 비밀번호를 두지 않고 Node 서버에서 scrypt 해시로 검증하며, 성공 시 12시간 만료 `HttpOnly`·`Secure`·`SameSite=Strict` 세션 쿠키를 발급한다. 접속지별 10분 내 5회 실패 시 추가 시도도 차단한다.

상품 대시보드에서 상품 검색·선택·신규 등록·수정이 가능하다. 상품명, 카테고리, 가격, 설명, 이미지 URL, 공식몰 URL, 배지, 추천 순서, 공개 여부, 판매 가능 상태를 편집할 수 있다. 삭제 대신 비공개 전환을 제공해 실수 복구가 가능하게 했다.

수정 데이터는 Git에 포함되지 않는 `data/products.json`에 원자적으로 저장해 PM2 재시작 후에도 유지된다. 기존 PM2 정적 서버를 전용 `server.mjs`로 교체하고 프로세스 목록을 저장했다.

임시 데이터·포트에서 401 미인증 차단, 잘못된 비밀번호 차단, 정상 로그인, 상품 20개 로드, 상품 수정 저장, 공개 API 반영, 로그아웃 후 재차단을 확인했다. 390px 모바일에서 로그인 카드와 상품 목록·편집 폼도 실제 렌더링해 가독성과 가로 넘침이 없음을 확인했다.

### 메인페이지 관리자 글 수정

기존 관리자 대시보드에 `메인페이지 글`과 `상품 관리` 탭을 분리했다. 메인페이지의 78개 문구를 6개 접이식 그룹으로 나눠 모바일에서도 필요한 섹션만 열어 수정할 수 있게 했다. 편집 범위는 첫 화면, 핵심 원칙, 제품몰 소개, 창업 12단계 제목·설명, 3개 상품 배너, 서류·실무·주의사항 섹션, 마지막 요약, 하단 회사 정보다.

공개 `GET /api/content`와 인증 후 `GET·PUT /api/admin/content`를 추가했다. 관리자가 저장한 글은 Git 제외 영역인 `data/content.json`에 원자적으로 저장되고, 방문자 페이지는 새로고침 시 API를 읽어 각 `data-content-key`요소에 안전하게 `textContent`로 반영한다. 전화번호와 사업자번호를 변경하면 `tel:` 및 공정거래위원회 정보확인 링크도 함께 갱신된다.

임시 서버에서 관리자 로그인, 필드 78개·그룹 6개 로드, 메인 제목 수정 저장, 공개 API 반영, 실제 방문자 DOM 문구 변경을 순서대로 확인했다. 390px 모바일에서 접이식 편집 그룹과 하단 저장 버튼을 실제 렌더링해 가독성과 가로 넘침이 없음을 확인했다.

## 2026-08-01 후속 체크포인트 · 내부 상품 상세 페이지와 상위 3개 콘텐츠

- 계획 커밋: 이 기록을 포함한 `feat(shop): add product details and top product content`
- 운영 주소: `https://sonsecha.dclub.kr/#shop`

### 요청을 해석한 방식

kim은 상품 관리에 공개·비공개 버튼을 추가하라고 했다가 이미 존재하는 것을 확인하고, 제품몰에 상품 상세 페이지를 추가하라고 범위를 교정했다. 이어 추천순 상위 3개는 이미지와 상세 글까지 직접 조사해 완성하라고 지시했다.

상세 페이지를 별도 외부몰 링크의 이름만 바꾸는 것으로 처리하지 않았다. 제품 카드에서 내부 상세 주소로 이동하고, 직접 접속·새로고침·뒤로가기·장바구니가 한 흐름으로 이어지는 제품몰 화면으로 구현했다. 기존 상품 저장구조와 외부 공식몰 링크는 유지했다.

### 내부 상품 상세 화면

- 상품 카드 이미지·상품명·`상세 보기`를 `#shop/product/상품ID`로 연결했다.
- 상세 화면에 공식 대표 이미지, 분류, 상품명, 요약, 가격·재고, 장바구니, 공식몰 연결, 상세 안내, 구매 전 확인 3단계와 같은 분류 상품을 표시한다.
- 브라우저 뒤로가기로 검색·분류 상태가 남은 상품 목록에 돌아가고 상세 주소를 새로고침해도 같은 상품이 열린다.
- 공개 API에서 찾을 수 없는 비공개·삭제 상품 ID는 상세 내용을 노출하지 않고 `공개 중인 상품을 찾을 수 없습니다` 화면을 표시한다.
- 디자인 라이브러리 `design-035 Web UI Kit`는 화면 전체가 아니라 버튼 상태 규칙만 참고했다. 현재 사이트의 navy/blue 카드 디자인을 유지하면서 normal, hover, active, focus, disabled 상태를 정의했다.
- 모바일에서는 상세 이미지·본문·버튼·관련상품을 한 열로 재배치해 가로 스크롤을 막았다.

### 관리자와 서버 데이터

- 상품 데이터에 선택 필드 `details`를 추가했다. 최대 4,000자이며 기존 상품에 값이 없으면 `summary`를 대신 표시한다.
- 관리자 상품 편집에 `상세 페이지 설명` 입력란을 추가했다.
- 서버 검증은 기존 필드를 그대로 유지하면서 `details`만 추가했다. 저장된 상품의 가격·재고·공개상태·추천순·공식몰 링크를 깨지 않는다.
- 전용 `scripts/browser-smoke-shop.mjs`는 임시 관리자 API에서 상세 설명 저장과 비공개 상품을 만든 뒤 공개 목록, 상세, 장바구니, 뒤로가기, 직접주소 새로고침과 390px 화면을 검증한다.

### 상위 3개 외부 조사와 콘텐츠

운영 `/api/products`의 실제 추천순을 기준으로 다음 세 상품을 정했다. 소스 기본 배열과 운영 저장 데이터가 달랐기 때문에 화면에 공개되는 운영 API를 정본으로 삼았다.

1. `k002-89` 하부세차기 (바닥매립형)
2. `k002-83` 폐수처리기 폐수계량기 40A
3. `k002-20` 셀프세차장 폐수처리기 약품 (하나로 or AB)

`agent-reach`의 Exa 검색을 먼저 호출했지만 현재 mcporter에 Exa 서버가 없어 `Unknown MCP server 'exa'`로 실패했다. 다음 공식 경로인 Jina Reader로 세 K002 상품 페이지를 직접 읽고, 공식 이미지 파일을 내려받아 제품 사진과 해상도를 확인했다. 화학제품 안전 문구는 안전보건공단 MSDS 공식 안내로 교차 확인했다.

- 하부세차기는 K002가 명시한 `토목공사시 매립`, `레미콘 아래 설치`, `별도 공사 필요`를 제품 사실로 사용했다. 차량 동선·배수·급수·타설 전 점검은 설치 전 확인 항목으로 분리했다.
- 폐수계량기는 공식 페이지에 있는 40A, 대한민국 원산지와 제품 사진만 확정 사실로 썼다. 유량·압력·온도·연결 규격은 공개되지 않았으므로 임의 수치를 만들지 않고 주문 전 판매자 확인사항으로 표시했다.
- 폐수처리 약품은 공식 상품명과 HWC 폐수약품 이미지를 사용했다. 성분·용량·투입비가 공개되지 않았음을 밝히고, 임의 혼합·투입 대신 기존 처리 방식과 공급자가 제공하는 MSDS·경고표지 확인을 안내했다.

세 상품의 장문 `details`와 개선된 `summary`를 소스 기본 데이터에 남겼다. 운영 데이터는 관리자 API로 같은 필드와 기존 공식 대표 이미지만 갱신했고 가격·재고·공개상태·추천순·공식몰 링크는 보존했다. 세 건 중 하나라도 실패하면 앞서 변경한 상품을 역순으로 되돌리도록 실행했다.
