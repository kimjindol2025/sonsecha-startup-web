# 제품몰·장바구니·간이견적서 체크포인트

- 날짜: 2026-07-31 KST
- 운영 주소: `https://sonsecha.dclub.kr/#shop`
- 계획 체크포인트: 이 기록과 구현을 함께 담는 `feat(shop)` 커밋

## 요청 해석

사용자는 기존 손세차장 창업 안내 사이트에 회사 판매 제품을 올릴 수 있는 탭을 만들고, 품목별 카테고리와 장바구니를 갖춘 실제 쇼핑몰 형태로 구성하라고 요청했다. 상품 등록은 나중에 진행한다고 명시했다. 후속 요청에서는 장바구니 상품을 견적서 형태의 폼으로 볼 수 있게 해 달라고 했다.

현재 프로젝트는 Vite 정적 사이트이며 주문 서버, 관리자 인증, 이미지 저장소와 PG 결제가 없다. 따라서 이번 체크포인트는 상품 데이터만 추후 넣으면 작동하는 공개 카탈로그, 브라우저 장바구니, 전화 견적 연결과 인쇄 가능한 간이견적서를 구현하는 범위로 정했다.

## 구현 내용

### 제품몰

- 상단 메뉴와 본문에 `제품몰` 탭을 추가했다.
- 전체 상품, 세차 케미컬, 세차 도구, 장비·부품, 안전·관리용품 카테고리를 만들었다.
- 상품명 검색과 추천순·상품명순·가격순 정렬을 구현했다.
- 상품 카드에 이미지, 배지, 카테고리, 상품명, 설명, 가격, 재고와 담기 버튼을 표시할 수 있다.
- 상품 데이터는 `src/products.js`에서 관리하며 현재 공개 배열은 사용자의 지시대로 비어 있다.
- 상품이 없을 때 판매 준비 중 안내와 제품 상담 전화가 표시된다.

### 장바구니

- 상단과 제품몰 헤더에 장바구니 수량 배지를 추가했다.
- 상품 담기, 삭제, 1~99개 수량 변경과 예상 합계를 구현했다.
- 가격 미정 상품은 `가격 문의`로 표시하고 금액 합계에는 포함하지 않는다.
- 장바구니는 `localStorage`의 `sonsecha-shop-cart-v1`에 저장한다.
- 문의 상품 목록 복사와 `031-1688-7759` 전화 주문·견적 문의를 제공한다.

### 간이견적서

- 장바구니가 비어 있지 않을 때 `견적서 작성` 버튼을 활성화한다.
- 견적번호, 작성일, 14일 유효기간과 상품명·단가·수량·금액·상품 합계를 자동 생성한다.
- 받는 회사·상호, 담당자, 연락처, 이메일, 배송·설치 주소와 요청사항 입력 폼을 제공한다.
- 공급자 영역에는 대표이사 김진돌, 사업자등록번호 127-38-49368, 회사 주소와 문의전화를 넣었다.
- 고객 입력은 `localStorage`의 `sonsecha-quote-form-v1`에 자동 저장하고 재방문 시 복원한다.
- 견적 내용 복사와 브라우저 인쇄·PDF 저장을 제공한다.
- 배송비, 설치비, 부가세 적용과 재고는 최종 상담에서 확정된다는 문구를 명시했다.

- `git diff --check`: 공백 오류 없음
- 임시 테스트 상품 장바구니 검증
  - 25,000원 상품 담기, 수량 2개, 합계 50,000원
  - 장바구니 배지와 브라우저 저장 확인
- 임시 테스트 상품 견적서 검증
  - 모바일 390px에서 가로 넘침 없음
  - 상품 1개, 합계 33,000원 자동 반영
  - 고객 회사·담당자·연락처·이메일·주소·요청사항 저장 및 새로고침 복원
  - 인쇄용 PDF 219,642바이트 생성 성공
- 최종 빌드에서 두 임시 테스트 상품과 테스트 문구가 제거된 것을 확인
- PM2 `sonsecha-startup-web` 재시작 후 공개 HTML과 최신 JS 번들 반영 확인
- PM2 오류 로그 없음

## 사용자 교정과 판단 기록

- 처음에는 공개 카탈로그와 직접 관리하는 관리자 페이지 중 선택이 필요하다고 판단해 질문했다. 사용자는 실제 쇼핑몰 형태와 장바구니를 원하되 상품 등록은 추후라고 범위를 확정했다. 이에 관리자·서버 기능을 억지로 추가하지 않고 상품 데이터 파일과 구매 UI 기반부터 만들었다.
- 첫 제품몰 반영은 장바구니와 전화 견적 문의까지였다. 사용자가 장바구니 내용을 견적서 폼으로 보여 달라고 요청해 고객정보 입력, 자동 품목표, 공급자 정보, 복사와 PDF 출력까지 확장했다.
- 실제 상품이 없는 상태에서는 장바구니와 견적서 경로를 검증할 수 없었다. 임시 상품을 코드에 넣어 브라우저 자동 검증한 뒤 반드시 제거하고 다시 빌드했다. 다음 작업자도 상품 데이터가 비어 있다는 이유로 동작 검증을 생략하지 말아야 한다.

## 남은 위험과 다음 작업

- 공개 상품은 아직 0개다. 실제 상품명, 가격, 사진, 재고와 카테고리를 사용자에게 받아 `src/products.js`에 등록해야 한다.
- 현재 장바구니와 견적 정보는 각 이용자의 브라우저에만 저장된다. 다른 기기 공유, 회사 수신, 주문 이력과 재고 차감 기능은 없다.
- 온라인 결제와 서버 주문 접수에는 PG 계약, 주문 API, 관리자 인증, 개인정보 처리와 환불·배송 정책이 필요하다.
- 현재 견적서는 자동 생성되는 간이견적서다. VAT 포함 여부, 배송·설치비, 할인과 공식 직인·서명 정책이 확정되면 계산 구조와 문구를 교정해야 한다.
- 고객 입력값을 외부로 전송하지는 않지만 공용 기기에는 남을 수 있다. 서버 주문 기능을 만들 때 개인정보 수집 동의, 보관기간과 파기 절차를 함께 구현해야 한다.
- 상품 이미지 권장 규격과 등록 형식은 `docs/product-catalog.md`를 따른다.
