## 사용자 요청을 해석한 방식

사용자는 사이트를 무료로 배포하면서 “클릭할 수 있는 모든 것”을 자체 애널리스트로 만들 수 있는지 요청했다. 이를 외부 광고·유료 분석 SDK를 붙이는 요청이 아니라, 현재 서버가 방문자 상호작용을 항목별로 집계하고 기존 비밀번호 관리자 화면에서 조회하는 자체 클릭 분석 기능으로 해석했다.

무료 공개 서비스에 불필요한 개인정보가 쌓이지 않도록 방문자 ID, 이름, 전화번호, IP 주소, 사용자 입력값과 메모는 영구 저장하지 않는다. 서버는 남용 방지 목적으로 접속 주소별 분당 횟수를 메모리에서만 제한하며 파일에는 기록하지 않는다.

## 변경 내용

### 방문자 클릭 자동 분류

- `src/analytics.js`를 추가하고 이벤트 위임으로 동적 상품과 장바구니까지 한 곳에서 수집한다.
- 상단 메뉴, 페이지 탭, 로드맵 단계·상세·판정, 후보지, 실무 체크, 세 개 상품 배너, 제품 분류, 상품별 공식몰 링크·장바구니 담기, 장바구니 수량·삭제, 견적서, 전화와 외부 링크를 의미 있는 고정 ID로 분리한다.
- 검색·후보지·견적 입력칸은 클릭한 필드 이름만 기록하며 입력한 검색어, 주소, 담당자, 연락처와 메모 값은 전송하지 않는다.
- 같은 `#shop` 링크를 쓰는 세 개 로드맵 배너는 화면 순번으로 분리하고, 쿼리 주소를 쓰는 공식몰 링크는 상품 ID로 분리한다.
- `sendBeacon`을 우선 사용해 외부 링크나 화면 전환 직전 클릭도 놓치지 않고, 지원되지 않으면 `fetch(..., keepalive: true)`로 대체한다.

### 자체 집계 API

- 공개 `POST /api/analytics/click`이 검증된 클릭 이벤트만 받는다.
- 일자 계산은 서버 환경과 관계없이 `Asia/Seoul` 기준으로 고정했다.
- 클릭별 누적, 날짜별 횟수, 모바일·태블릿·PC 구분을 `data/analytics.json`에 원자적으로 저장한다.
- 운영 집계 파일은 기존 `data/` 제외 규칙을 따라 Git에 포함되지 않으며 파일 권한은 `0600`이다.
- 날짜별 상세 집계는 최근 366일만 유지하고 클릭 항목 수는 최대 2,000개, 접속 주소별 수집은 분당 120회로 제한한다.
- 인증된 `GET /api/admin/analytics?range=7|30|90|365`만 분석 결과를 제공한다.

### 관리자 분석 대시보드

- 기존 관리자에 `클릭 분석` 세 번째 탭을 추가했다.
- 오늘, 최근 7일, 최근 30일, 전체 누적 수치를 한눈에 표시한다.
- 기간별 막대 추이, 기기별 누적 비율, 클릭 항목별 위치·종류·기간 횟수·누적·최근 시각을 제공한다.
- 7일·30일·90일·1년 범위 변경, 새로고침과 항목명·위치 검색을 제공한다.
- 560px 이하에서는 통계가 2열로 재배치되고 클릭 순위 표가 항목별 카드로 바뀐다.

## 실수와 교정

- 처음에는 사용자의 “애널리스트” 표현을 자체 클릭 분석으로 해석하고 바로 구현했다. 다음 작업자는 이 표현이 방문자 행동 집계를 뜻한다는 현재 문맥을 유지하되, 주문 전환이나 페이지 조회처럼 범위를 확장할 때는 지표 정의를 먼저 기록해야 한다.
- 첫 자동 분류안에서는 K002 공식몰 링크의 쿼리 문자열을 개인정보 방지를 위해 제거해 상품별 링크가 하나로 합쳐질 수 있었다. 링크 주소 대신 이미 공개된 상품 ID를 집계 키로 사용하도록 교정했다.
- 세 개 로드맵 배너도 목적지가 모두 `#shop`이라 하나의 링크로 합쳐질 수 있었다. 배너 순번과 제목을 기준으로 각각 분리했다.
- 후보지 선택은 브라우저별 임의 후보지 ID를 그대로 쓰면 항목 수가 불필요하게 늘 수 있어, 후보지 이름이나 ID를 보내지 않고 하나의 `후보지 선택` 행동으로 집계했다.
- 테스트 Chrome의 최초 창 크기는 명령 인수와 달리 500px로 열렸다. DevTools 모바일 에뮬레이션을 390×844로 다시 고정하고 장바구니 동작과 관리자 가로 폭을 재검증했다.

## 남은 위험과 다음 작업

- 클릭 수는 관심도를 보여주지만 실제 방문자 수나 구매 전환율과 같지 않다. 현재는 개인정보 최소화를 위해 고유 방문자·세션 추적과 페이지뷰를 의도적으로 넣지 않았다.
- `data/analytics.json`은 Git 제외 운영 데이터다. 장기 운영 전에는 `products.json`, `content.json`과 함께 별도 백업 대상에 포함해야 한다.
- 공개 수집 API는 메모리 기반 속도 제한과 항목 수 상한을 두었지만, 대규모 트래픽에서는 파일 1개 쓰기 대신 데이터베이스나 배치 저장을 검토해야 한다.
- 관리자 분석은 조회 전용이다. CSV 내보내기, 기간 비교, 집계 초기화는 아직 범위 밖이다.
