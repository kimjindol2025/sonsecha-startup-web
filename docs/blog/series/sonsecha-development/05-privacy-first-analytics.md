# 5부 · 무료 서비스의 자체 클릭 분석

- 연재: 손세차장 창업 로드맵 개발기 5/7
- 기록일: 2026-08-01 KST
- 관련 커밋: `f494571`

## 무료로 공개하되 무엇이 쓰이는지는 알아야 했다

사용자는 각 항목의 모든 클릭을 “우리 애널리스트”로 만들 수 있는지 물었다. 외부 광고 SDK나 유료 분석 서비스를 붙이는 대신 현재 서버가 직접 집계하고 관리자에서 확인하는 구조를 선택했다.

수집 대상은 메뉴, 탭, 12단계 체크와 상세, 후보지 행동, 실무 체크, 상품 배너, 상품 분류, 공식몰 링크, 장바구니, 견적서, 전화와 외부 링크다. 검색·주소·견적 입력칸은 사용 여부만 기록하고 실제 입력값은 보내지 않는다.

## 개인정보 없이 집계하기

- 방문자 ID, 이름, 전화번호와 입력 내용 미수집
- IP는 파일에 저장하지 않고 속도 제한을 위한 메모리 키로만 임시 사용
- KST 기준 날짜별 클릭 횟수
- 모바일·태블릿·PC 구분
- 항목별 누적과 최근 클릭 시각
- 최근 366일 상세 집계, 항목 최대 2,000개

관리자 `클릭 분석` 탭은 오늘·7일·30일·누적 수치, 날짜별 추이, 기기 비율, 항목 순위와 기간 검색을 제공한다.

## 자동 분류에서 생긴 오류

첫 구현은 URL의 쿼리 문자열을 제거했다. 이 때문에 K002 상품 상세주소가 같은 경로로 합쳐질 수 있었다. 상품 ID를 집계 키로 사용해 상품별로 분리했다.

세 개 로드맵 배너도 모두 `#shop`으로 이동하므로 하나의 링크로 합쳐질 수 있었다. 배너 순번과 제목을 별도 키로 만들었다. 후보지 선택은 반대로 브라우저마다 다른 임의 ID를 저장하지 않고 하나의 행동으로 합쳤다.

항목을 세밀하게 나누는 것과 사용자를 식별하는 것은 다른 문제다. 운영에 필요한 행동 단위만 구분하고 개인 단위 추적은 넣지 않았다.
