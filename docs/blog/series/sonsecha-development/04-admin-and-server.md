## 상품을 계속 수정하려면 서버가 필요했다

사용자는 비밀번호만 입력하는 관리자 모드, 상품 대시보드와 메인페이지 글 수정을 요청했다. 정적 JavaScript에 관리자 비밀번호를 넣으면 누구나 소스에서 볼 수 있고, 수정 내용도 서버에 남지 않는다.

그래서 정적 파일만 제공하던 구조를 `server.mjs` 기반 Node 서버로 바꿨다. PM2는 같은 프로젝트의 `dist/`와 API를 함께 제공한다.

## 비밀번호 전용 관리자

“비밀번호만 입력”은 아이디 입력란이 없다는 뜻으로 구현하되 인증 자체는 서버에서 처리했다.

- scrypt 해시와 임의 salt만 저장
- 12시간 만료 HttpOnly·Secure·SameSite 쿠키
- 10분 동안 5회 실패 시 일시 차단
- 운영 인증 파일과 콘텐츠 파일은 `data/`에 저장하고 Git 제외
- 비밀번호 변경 후 모든 세션 종료

초기 비밀번호 원문은 코드, 블로그와 커밋에 기록하지 않았다.

## 상품과 메인 글 관리

상품 관리자는 상품명, 분류, 가격, 설명, 이미지, 공식몰 URL, 배지, 추천 순서, 공개와 판매 상태를 수정한다. 삭제 대신 비공개 전환을 제공해 운영 실수를 복구할 수 있게 했다.

메인페이지는 일부 문장만 바꾸는 방식으로 축소하지 않았다. 첫 화면, 핵심 원칙, 제품몰, 12단계, 3개 배너, 안내 섹션과 회사 정보까지 78개 필드를 6개 그룹으로 나눴다. 저장된 내용은 `data/content.json`에 원자적으로 기록되고 방문자 화면은 안전하게 `textContent`로 반영한다.

## 복사 비밀번호 공백 문제

운영 배포 후 사용자는 비밀번호가 맞지 않는다고 보고했다. 저장된 해시와 전달받은 문자열은 일치했고 로컬·공개 API도 인증에 성공했다. 화면의 마스킹 문자 수가 원래보다 2개 많아 복사 과정에서 앞뒤 공백이 포함된 것으로 판단했다.

비밀번호 변경 시에는 이미 공백을 제거해 저장했지만 로그인 비교에서는 그대로 사용하던 비대칭이 원인이었다. `b025894`에서 브라우저 전송 직전과 서버 비교 직전에 앞뒤 공백만 제거하도록 교정했다. 운영 서버에서 공백을 일부러 붙인 로그인도 성공하는지 확인했다.
