## 현재 구조

프로젝트는 더 이상 단순 정적 안내 페이지가 아니다.

- Vite 멀티페이지 빌드: 방문자 `index.html`, 관리자 `admin.html`
- Node `server.mjs`: 정적 파일과 공개·관리 API 제공
- PM2: `sonsecha-startup-web`, 포트 `40330`, production 모드
- 브라우저 저장: 후보지, 체크, 메모, 장바구니, 견적 입력
- 서버 JSON: 상품, 메인 콘텐츠, 인증 해시, 클릭 분석
- 서버 SQLite: 사용자 피드백과 처리 상태

## 검증 원칙

이 프로젝트에서 “빌드 성공”만으로 완료를 판단하지 않았다.

1. JavaScript 문법 검사와 Vite 운영 빌드
2. `git diff --check`와 의도한 파일 범위 확인
3. 임시 데이터 디렉터리에서 API 정상·오류·인증 경로 검증
4. 390px Chrome에서 실제 클릭, 저장과 가로 넘침 확인
5. Gogs 커밋과 원격 정렬 확인
6. PM2 재시작 후 공개 HTTPS 응답 확인
7. 테스트 인증·DB·브라우저 프로필 삭제

운영 DB를 오염시키지 않기 위해 쓰기 테스트는 임시 DB에서 수행하고, 공개 운영에서는 스팸 함정처럼 저장되지 않는 경로를 활용했다.

## 반복하지 말아야 할 실수

- 모바일 자동 캡처가 정상이라고 실제 가독성이 끝난 것으로 판단하지 않는다.
- “탭”을 단순 앵커 링크로 축소하지 않는다.
- 후보지 데이터는 주소마다 독립시킨다.
- 사용자가 지정한 상품·순서·이미지를 임의 대체하지 않는다.
- 본문 기능을 수정하면서 회사 고정정보를 누락하지 않는다.
- 정적 소스에 관리자 비밀번호를 넣지 않는다.
- 분석 이벤트를 지나치게 합치거나 개인 식별자로 지나치게 분리하지 않는다.
- 운영 DB에 검증용 게시물을 남기지 않는다.

## 백업이 필요한 운영 데이터

`data/`는 Git에서 제외된다. 따라서 Gogs 푸시만으로 다음 파일을 복구할 수 없다.

- `admin-auth.json`
- `products.json`
- `content.json`
- `analytics.json`
- `feedback.sqlite`

정기 백업과 복원 절차가 다음 운영 과제다. 특히 상품·콘텐츠·피드백은 사용자와 관리자가 만든 실제 운영 기록이다.

## 다음 우선순위

1. 실제 방문자의 클릭과 피드백을 일정 기간 관찰한다.
2. 많이 쓰이는 항목과 불편 의견을 근거로 다음 기능을 결정한다.
3. 실기기 iPhone Safari와 Android Chrome에서 반복 검증한다.
4. 운영 데이터 자동 백업을 만든다.
5. 피드백이 늘면 페이지네이션, 관리자 메모와 내보내기를 검토한다.
6. 주문·결제는 수요와 개인정보 처리정책이 확정된 뒤 별도 범위로 설계한다.
