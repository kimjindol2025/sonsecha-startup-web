## 사용자 요청을 해석한 방식

사용자는 초기에 모바일 가독성과 하단 회사 정보를 요청했고, 이후 제품몰·장바구니·견적서·K002 상품 등록·로드맵 사이 배너로 범위를 확장했다. 마지막에는 비밀번호만 입력하는 관리자 모드, 상품 등록·수정 대시보드, 메인페이지 글 수정을 요청했다.

“비밀번호만 입력”은 로그인 화면에 아이디를 요구하지 않는다는 의미로 해석했다. 비밀번호를 정적 JavaScript에 넣는 방식은 소스에 노출되고 상품 수정을 서버에 저장할 수 없으므로, 기존 PM2 정적 서버를 전용 Node 서버로 교체하는 것까지 요청 범위에 포함했다.

## 변경 내용

### K002 상품과 로드맵 배너

- K002 `ps_ctid=01000000` 카테고리의 공개 상품 12개를 이름·가격·이미지·상세 링크와 함께 추가했다.
- 기존 샘플 8개를 유지해 전체 20개 상품이다.
- 원문에 품절 표시가 있는 `하부세차기 (바닥매립형)`은 노출하되 장바구니 버튼을 비활성화했다.
- 로드맵 3·7·10번 다음 배너를 각각 폐수처리기, 고압세척기, 콤프레셔로 교체했다.

### 상품 관리자

- `/admin.html`에 비밀번호 전용 로그인을 추가했다.
- 비밀번호는 scrypt 해시로만 `data/admin-auth.json`에 저장하고, 운영 데이터 전체를 `.gitignore`로 제외했다.
- 세션은 12시간 만료 `HttpOnly`·`Secure`·`SameSite=Strict` 쿠키를 사용한다.
- 접속지별 10분 내 5회 로그인 실패 시 잠시 차단한다.
- 상품명, 카테고리, 가격, 설명, 이미지, 공식몰 링크, 배지, 추천 순서, 공개·판매 상태를 수정할 수 있다.
- 새 상품 등록을 제공하고, 삭제 대신 비공개 전환으로 실수 복구가 가능하게 했다.

### 메인페이지 글 관리

- 관리자 대시보드를 `메인페이지 글`과 `상품 관리` 탭으로 분리했다.
- 메인페이지의 78개 문구를 첫 화면, 핵심 원칙·제품몰, 창업 12단계, 상품 배너, 안내 섹션, 회사 정보 6개 그룹으로 정리했다.
- 저장한 글은 `data/content.json`에 원자적으로 쓰고, 방문자 페이지가 `GET /api/content`를 읽어 `textContent`로 반영한다.
- 전화번호와 사업자번호 수정 시 `tel:`과 사업자 정보확인 링크도 갱신한다.

### 운영 서버

- `server.mjs`가 `dist/`를 제공하고 공개 상품·콘텐츠 API와 인증된 관리 API를 같이 처리한다.
- `ecosystem.config.cjs`로 PM2 실행 구성을 고정했고 운영 프로세스는 포트 `40330`에서 정상 운영 중이다.
- Vite를 멀티페이지 빌드로 변경해 `index.html`과 `admin.html`을 함께 빌드한다.

## 실수와 교정

- 초기 배너를 임의 K002 상품으로 구성했지만, 사용자가 1번 폐수처리기·2번 고압세척기·3번 콤프레셔와 정확한 이미지 URL을 지정했다. 이후 지정 순서와 URL을 기준으로 다시 교체했다.
- 초기 상품몰은 K002 샘플 8개만 있었지만, 사용자가 특정 카테고리 전체 상품을 요청해 카테고리 원문을 다시 읽고 12개를 모두 추가했다.
- “관리자 비번”을 클라이언트 전용 기능으로 만들면 상품 수정이 단말 내에만 남는다. 이를 피하기 위해 전용 서버·해시 인증·영속 저장을 함께 구현했다.
- 메인 글 관리는 첫 화면 몇 문구만 수정하는 것으로 축소하지 않고, 12단계·배너·회사 정보까지 실제 반복 수정 가능한 필드로 분리했다.

## 남은 위험과 다음 작업

- K002 상품 이미지는 원격 URL을 직접 사용하므로 원본 경로가 바뀌면 깨질 수 있다.
- `data/products.json`과 `data/content.json`은 Git 제외 운영 데이터이므로 주기적 백업 정책이 필요하다.
- 최초 관리자 비밀번호는 접속 후 대시보드에서 운영자 전용 비밀번호로 변경해야 한다. 비밀번호 자체는 이 문서와 Git에 기록하지 않았다.
- 온라인 결제, 서버 주문 저장, 재고 수량 차감, 배송조회는 아직 범위 밖이다.
